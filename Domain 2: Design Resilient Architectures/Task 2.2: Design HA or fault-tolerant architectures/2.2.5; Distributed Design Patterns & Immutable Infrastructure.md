
# Distributed Design Patterns & Immutable Infrastructure
 

## 1. Distributed Design Patterns

### 1.1 What are distributed systems?

A distributed system consists of multiple independent services, applications, or computing resources that communicate over a network to deliver a single business function.

Instead of running everything in one application, responsibilities are divided into smaller, loosely coupled components.

Example: E-commerce application

- User Service – manages customer accounts.
- Product Service – manages product information.
- Order Service – processes orders.
- Payment Service – processes payments.
- Notification Service – sends emails and messages.

### 1.2 Common distributed design patterns

| ------------------------- | --------------------------------------------------- | ------------------------------------ |
| Microservices             | Break an application into independent services.     | ECS, EKS, Lambda                     |
| Event-driven architecture | Services communicate through events.                | EventBridge, SNS                     |

### 1.3 Important distributed design patterns

#### A. Microservices Pattern

An application is divided into smaller independent services. Each service performs a specific business function and can be deployed and scaled independently.

Example architecture:

```
             Users
               |
        Amazon API Gateway
               |
       Application Services
          /    |     \
         /     |      \
      User   Order   Payment
     Service Service  Service
        |      |       |
      DynamoDB RDS   DynamoDB
```

Benefits:

- Independent deployment.
- Independent scaling.
- Technology flexibility.
- Better fault isolation.
- Faster development.

Challenges:

- Network communication complexity.
- Distributed data management.
- Monitoring and troubleshooting.
- Service-to-service security.

#### B. Event-Driven Architecture

Services communicate by producing and consuming events instead of relying entirely on direct synchronous communication.

Example:

```
       Order Service
             |
        Order Created
             |
      Amazon EventBridge
        /      |       \
       /       |        \
   Payment  Inventory  Notification
   Service   Service     Service
```

AWS services:

- Amazon EventBridge – event routing.
- Amazon SNS – publish/subscribe messaging.
- Amazon SQS – message queues.
- AWS Lambda – event processing.

Benefits:

- Loose coupling.
- Asynchronous processing.
- Improved scalability.
- Independent service development.

#### C. Queue-Based Architecture

A queue stores messages until a consumer processes them. Producers and consumers do not need to communicate directly.

```
 Application
     |
  Amazon SQS
     |
  Consumer
     |
  Database
```

Benefits:

- Handles traffic spikes.
- Decouples application components.
- Supports asynchronous processing.
- Improves fault tolerance.

Important: Configure message visibility timeouts, retries, dead-letter queues (DLQs), and idempotent consumers.

#### D. Circuit Breaker Pattern

Prevents an application from continuously calling a service that is experiencing failures.

Three states:

1. Closed: Requests flow normally.
2. Open: Requests are blocked after a failure threshold is reached.
3. Half-open: Limited test requests determine whether the service has recovered.

```
Application
     |
Circuit Breaker
     |
Payment Service
     |
  Database
```

Benefits:

- Prevents cascading failures.
- Reduces unnecessary requests.
- Improves system resilience.

AWS implementation example: Step Functions with DynamoDB to track circuit status.&#x20;

#### E. Saga Pattern

Coordinates a business transaction across multiple independent services.

Instead of using one database transaction across all services, each service executes a local transaction. If a step fails, compensating transactions can reverse previously completed business actions.

Example: Online order processing

```
Create Order
     |
Process Payment
     |
Reserve Inventory
     |
Arrange Shipment
     |
Order Completed
```

If inventory reservation fails, the payment service can execute a refund as a compensating transaction.

AWS implementation: AWS Step Functions for orchestration or event-driven choreography using EventBridge.

#### F. Retry with Exponential Backoff

When a temporary failure occurs, the application retries the request after progressively increasing delays.

Example:

```
1st retry:  1 second
2nd retry:  2 seconds
3rd retry:  4 seconds
4th retry:  8 seconds
```

Add random jitter to reduce simultaneous retry traffic.

Benefits:

- Handles temporary network failures.
- Reduces pressure on overloaded services.
- Improves recovery from transient errors.

Use timeouts, retry limits, and idempotency to avoid duplicate operations.

AWS recommends controlling retries, throttling requests, using timeouts, and making systems stateless where possible.&#x20;

## 2. Immutable Infrastructure

### 2.1 What is immutable infrastructure?

Immutable infrastructure is an infrastructure management approach in which existing production servers or infrastructure resources are never modified directly.

When an application update, security patch, or configuration change is required, a new infrastructure environment is created with the updated configuration. After validation, traffic is transferred to the new environment.

Key principle: Build new infrastructure instead of modifying existing infrastructure.

### 2.2 Mutable vs Immutable Infrastructure

| Feature       | Mutable Infrastructure       | Immutable Infrastructure      |
| ------------- | ---------------------------- | ----------------------------- |
| Updates       | Modify existing servers      | Replace with new servers      |
| Configuration | Changes over time            | Version-controlled            |
| Deployment    | In-place updates             | New deployment                |
| Consistency   | Configuration drift possible | More consistent               |
| Rollback      | Can be complicated           | Restore previous version      |
| Security      | Manual patching possible     | Rebuild with security patches |
| Automation    | Often partially automated    | Highly automation-friendly    |

Workflow:

3. CI/CD pipeline starts the build process.

5. Security scanning and automated tests are performed.
6. New EC2 instances are launched using the updated AMI.
7. Health checks validate the new instances.
8. Traffic is shifted to the new environment.
9. Old instances are terminated after successful deployment.

### 2.5 Immutable Infrastructure Deployment Strategies

#### A. Blue/Green Deployment

Two environments are maintained:

- Blue: Current production environment.
- Green: New application version.

[New – Application Load Balancer Simplifies Deployment with Weighted Target Groups | AWS News Blog](https://images.openai.com/static-rsc-4/PFmezdQqVht_ne6xYpl15QTilm1as1FPqgUwnrtuZbkyrW7gKWMHYU_FAgEhcbnBV7cycXXiwabbUDdbuSszq4H5H5ZcPQjKzlTq7851elmA1qQZucaYTnOU3QdNQ1kL0Hh2sA_umM8bM_Y7vZXqsJGWy760hKBv3cT74ORnsaM?purpose=inline)

[aws.amazon.com](https://aws.amazon.com/blogs/aws/new-application-load-balancer-simplifies-deployment-with-weighted-target-groups/?utm_source=chatgpt.com)

Deployment process:

1. Blue environment serves production traffic.
2. Green environment is created with the new version.
3. Automated testing is performed on Green.
4. Traffic is switched from Blue to Green.
5. Blue is retained temporarily for rollback.
6. Blue is removed when no longer required.

Benefits:

- Minimal downtime.
- Fast rollback.
- Safer production releases.
- Environment isolation.

#### B. Canary Deployment

A new application version is released to a small percentage of users before a full rollout.

Example:

- 95% traffic → Version 1.
- 5% traffic → Version 2.

- Gradually increase traffic to Version 2.

### 2.6 Infrastructure as Code (IaC)

Infrastructure as Code means defining and managing infrastructure through configuration files or programming languages instead of manually creating resources.

AWS IaC tools:

- AWS CloudFormation – YAML/JSON infrastructure templates.
- AWS CDK – infrastructure definitions using programming languages.
- Terraform – third-party infrastructure provisioning tool.

Example: CloudFormation

```
AWSTemplateFormatVersion: '2010-09-09'

Resources:
  WebServer:
    Type: AWS::EC2::Instance
    Properties:
      ImageId: ami-xxxxxxxx
      InstanceType: t3.micro
```

The example illustrates the resource definition; replace the AMI ID with a valid AMI for the target Region.

Benefits:

- Repeatable infrastructure.
- Version control.
- Automated provisioning.
- Consistent environments.
- Easier disaster recovery.

AWS recommends storing infrastructure templates in version control and validating changes through automated testing and CI/CD pipelines.&#x20;

### 2.7 Benefits and Challenges

Benefits

1. Consistent infrastructure deployments.
2. Reduced configuration drift.
3. Easier rollback and recovery.
4. Improved security patch management.
5. Better auditability.
6. Automated deployment processes.
7. More predictable production environments.

Challenges

1. Additional infrastructure cost during parallel deployments.
2. Requires reliable CI/CD pipelines.
3. Requires automated testing.
4. Stateful applications need careful data migration.
5. Externalized configuration and secrets must be managed securely.
6. Database schema changes require backward-compatible migration strategies.

Important: Immutable infrastructure does not mean application data must be immutable. Persistent data should be stored separately using services such as Amazon RDS, Amazon S3, or Amazon DynamoDB.

## 3. Distributed Design Patterns vs Immutable Infrastructure

| Area               | Distributed Design Patterns           | Immutable Infrastructure             |
| ------------------ | ------------------------------------- | ------------------------------------ |
| Main focus         | Communication between services        | Infrastructure lifecycle             |
| Objective          | Reliability and scalability           | Consistency and repeatability        |
| Key concept        | Loose coupling                        | Replace, don't modify                |
| AWS services       | SQS, SNS, EventBridge, Step Functions | EC2, AMI, CloudFormation, CodeDeploy |
| Main benefit       | Fault isolation                       | Reduced configuration drift          |
| Common application | Microservices                         | CI/CD deployments                    |
