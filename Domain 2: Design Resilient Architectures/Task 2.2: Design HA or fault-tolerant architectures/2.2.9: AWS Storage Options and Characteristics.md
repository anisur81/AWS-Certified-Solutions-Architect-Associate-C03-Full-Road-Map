# AWS Storage Options and Characteristics

## 1. Introduction

AWS provides multiple storage services to store, manage, protect, and retrieve data. Each service has different characteristics relating to:

- **Durability:** Ability to protect data against loss.
- **Availability:** Ability to access data when required.
- **Replication:** Creating and maintaining copies of data.
- **Performance:** Latency, IOPS, and throughput.
- **Scalability:** Ability to increase or decrease storage capacity.
- **Cost:** Storage, requests, data transfer, and retrieval charges.

AWS storage solutions are primarily categorized into three types:

1. Block Storage
2. File Storage
3. Object Storage

Selecting the correct storage solution depends on application requirements, data access patterns, performance, availability, and recovery objectives.

## 2. Types of AWS Storage

### 2.1 Block Storage

Block storage divides data into fixed-sized blocks. Applications and operating systems access these blocks as storage volumes.

**Amazon Elastic Block Store (EBS)**

- Provides persistent block-level storage for Amazon EC2.
- Supports low-latency and high-performance workloads.
- Can be attached and detached from EC2 instances.
- Supports encryption using AWS KMS.
- Supports snapshots for backup and recovery.
- EBS volumes are associated with a specific Availability Zone.
- Supports different volume types for different performance requirements.

**Use cases:**

- Operating system disks.
- Relational databases.
- Application servers.
- Transaction-processing systems.

**Durability and replication:**

- EBS volumes are designed for high availability and durability within an Availability Zone.
- EBS automatically replicates volume data within its Availability Zone to protect against hardware failure.
- EBS snapshots provide point-in-time backups stored in Amazon S3.
- Snapshots can be copied to another AWS Region for disaster recovery.

### 2.2 Instance Store

Amazon EC2 Instance Store provides temporary block-level storage physically attached to the host computer.

**Characteristics:**

- Very high I/O performance.
- Low latency.
- Temporary storage.
- Data is lost when an instance is stopped, hibernated, or terminated.
- Storage capacity depends on the EC2 instance type.

**Use cases:**

- Temporary application data.
- Caches.
- Temporary processing files.
- Distributed data processing.

**Important:** Instance Store is not suitable for data that must persist independently of the EC2 instance.

### 2.3 Object Storage

**Amazon Simple Storage Service (S3)**

Amazon S3 is an object storage service designed to store and retrieve virtually unlimited amounts of data.

**Characteristics:**

- Highly scalable.
- High durability.
- Access through APIs and HTTP-based interfaces.
- Supports versioning.
- Supports lifecycle management.
- Supports encryption at rest and in transit.
- Provides multiple storage classes.
- Supports cross-Region replication.

**Durability:**

Amazon S3 Standard is designed for **99.999999999% (11 nines) durability**.

This means AWS is designed to protect stored objects against data loss through redundant storage mechanisms.

**Replication:**

- Automatically stores data redundantly across multiple Availability Zones within a Region for S3 Standard.
- Supports Same-Region Replication (SRR).
- Supports Cross-Region Replication (CRR).
- Replication can help with disaster recovery, compliance, and geographic data distribution.

**Use cases:**

- Application backups.
- Static website hosting.
- Data lakes.
- Media and document storage.
- Log storage.
- Big data analytics.

### 2.4 File Storage

File storage organizes data into files and directories. It allows multiple systems to access shared files through network protocols.

**Amazon Elastic File System (EFS)**

- Fully managed, elastic file storage.
- Primarily supports Linux-based workloads through NFS.
- Multiple EC2 instances can access the same file system.
- Automatically scales as data grows.
- Supports encryption at rest and in transit.
- Provides Regional and One Zone storage configurations.

**Durability and replication:**

- Regional EFS stores data redundantly across multiple Availability Zones.
- Designed for high durability and availability.
- One Zone EFS stores data in a single Availability Zone and has different resilience characteristics.

**Use cases:**

- Shared application files.
- Web server content.
- Content management systems.
- Linux application environments.
- Shared development environments.

**Amazon FSx**

Amazon FSx provides fully managed file systems based on popular file system technologies.

Four major options:

| Service                     | Main Characteristics                            |
| --------------------------- | ----------------------------------------------- |
| FSx for Windows File Server | Native Windows file system and SMB support      |
| FSx for Lustre              | High-performance computing and machine learning |
| FSx for NetApp ONTAP        | Enterprise storage and advanced data management |
| FSx for OpenZFS             | High-performance Linux and ZFS-based workloads  |

FSx availability, replication, and recovery capabilities depend on the selected file system and deployment configuration.

## 3. AWS Storage Durability and Replication Comparison

| Storage Service     | Storage Type | Durability / Protection               | Replication                       |
| ------------------- | ------------ | ------------------------------------- | --------------------------------- |
| Amazon S3 Standard  | Object       | 99.999999999% designed durability     | Multi-AZ, SRR, CRR                |
| Amazon EBS          | Block        | Redundant storage within an AZ        | Snapshots and snapshot copies     |
| EC2 Instance Store  | Block        | Temporary; not persistent             | No automatic durable replication  |
| Amazon EFS Regional | File         | 99.999999999% designed durability     | Multi-AZ                          |
| Amazon EFS One Zone | File         | Single-AZ storage                     | No automatic multi-AZ replication |
| Amazon FSx          | File         | Depends on file system and deployment | Depends on configuration          |

**Note:** Durability and availability are different concepts. High durability does not guarantee that an application or its data will always be immediately accessible.

## 4. AWS Storage Classes

Amazon S3 provides different storage classes to optimize cost according to data access frequency.

| Storage Class                 | Characteristics                                              | Use Cases                     |
| ----------------------------- | ------------------------------------------------------------ | ----------------------------- |
| S3 Standard                   | Frequently accessed, multi-AZ                                | Application data              |
| S3 Intelligent-Tiering        | Automatically optimizes storage costs                        | Changing access patterns      |
| S3 Standard-IA                | Infrequent access, multi-AZ                                  | Backups and disaster recovery |
| S3 One Zone-IA                | Infrequent access, single-AZ                                 | Re-creatable secondary data   |
| S3 Glacier Instant Retrieval  | Archive with millisecond retrieval                           | Rarely accessed archives      |
| S3 Glacier Flexible Retrieval | Archive with retrieval options ranging from minutes to hours | Long-term archives            |
| S3 Glacier Deep Archive       | Lowest-cost long-term archive storage                        | Regulatory retention          |

**Important:** Glacier storage classes are part of Amazon S3.

## 5. Backup and Disaster Recovery

Backup and replication are important for protecting critical business data.

### AWS Backup

AWS Backup is a fully managed service that centralizes and automates backups across supported AWS services.

**Key features:**

- Centralized backup management.
- Scheduled backup plans.
- Backup policies.
- Backup retention management.
- Cross-Region backup copies.
- Cross-account backup support.
- Recovery and restore operations.

### Amazon EBS Snapshots

- Point-in-time backups of EBS volumes.
- Incremental snapshots.
- Stored using Amazon S3 infrastructure.
- Can restore volumes.
- Can be copied across AWS Regions.

### Amazon S3 Versioning

- Maintains multiple versions of an object.
- Helps recover accidentally deleted or overwritten objects.
- Works with lifecycle policies.
- Can be combined with replication.

### Cross-Region Replication (CRR)

CRR automatically replicates eligible S3 objects from a source bucket to a destination bucket in another AWS Region.

**Benefits:**

- Disaster recovery.
- Geographic data distribution.
- Compliance requirements.
- Improved data availability for regional applications.

## 8. SAA-C03 Exam Tips

Remember these important points:

1. **Amazon S3:** Object storage with 11 nines of designed durability.
2. **Amazon EBS:** Persistent block storage for EC2.
3. **EBS snapshots:** Point-in-time backups stored using Amazon S3.
4. **Instance Store:** Temporary storage; data does not persist after instance stop or termination.
5. **Amazon EFS:** Shared, elastic file storage for multiple Linux instances.
6. **Amazon FSx:** Managed file systems for Windows, Lustre, NetApp ONTAP, and OpenZFS.
7. **S3 CRR:** Replicates objects across AWS Regions.
8. **S3 Versioning:** Helps recover previous object versions.
9. **S3 Glacier:** Cost-effective archival storage.
10. **AWS Backup:** Centralized backup management across supported AWS services.
