# API creation and management (Amazon API Gateway, REST API)

An Application Programming Interface (API) allows different applications and services to communicate with each other.

**Amazon API Gateway** is a fully managed AWS service for creating, publishing, securing, monitoring, and managing APIs at any scale.

It enables developers to expose backend services such as:
- AWS Lambda functions
- Amazon EC2 applications
- Container-based applications
- Other HTTP endpoints
- AWS services

API Gateway supports REST APIs, HTTP APIs, and WebSocket APIs.

## 2. API Gateway API Types

| API Type | Purpose | Use Case |
|---|---|---|
| REST API | Feature-rich request/response APIs | Enterprise applications |
| HTTP API | Lower-cost, lower-latency HTTP APIs | Serverless applications |
| WebSocket API | Two-way communication | Chat and real-time applications |

**Key differences:**
- REST APIs provide advanced features such as API keys, usage plans, request validation, caching, and AWS WAF integration.
- HTTP APIs provide a simpler, cost-effective API option.
- WebSocket APIs support persistent, bidirectional connections.

## 3. REST API Architecture

A REST API uses HTTP methods to access resources.

Common HTTP methods:

| Method | Purpose | Example |
|---|---|---|
| GET | Retrieve data | Get customer details |
| POST | Create data | Create a customer |
| PUT | Replace or update a resource | Update customer details |
| PATCH | Partially update data | Change customer email |
| DELETE | Remove a resource | Delete a customer |

### API Gateway Architecture

```text
Client Application
       |
       v
 Amazon API Gateway
       |
       v
 API Resource and Method
       |
       v
 Integration Endpoint
       |
       +---- AWS Lambda
       |
       +---- EC2 / HTTP Backend
       |
       +---- Other AWS Services
       |
       v
 Response to Client
```

## 4. Core Components of REST API

| Component | Description |
|---|---|
| RestApi | Represents the complete API |
| Resource | Represents an endpoint or path |
| Method | Defines HTTP operations such as GET and POST |
| Integration | Connects an API method to a backend |
| Integration Request | Sends client requests to the backend |
| Integration Response | Processes backend responses |
| Model | Defines request or response data structures |
| Authorizer | Controls API access |
| Deployment | Creates a callable snapshot of the API |
| Stage | Represents an environment such as dev, test, or prod |

### Example

```text
API: CustomerAPI

Resources:
/customers
/customers/{customerId}

Methods:
GET    /customers
POST   /customers
GET    /customers/{customerId}
PUT    /customers/{customerId}
DELETE /customers/{customerId}
```

## 5. Creating a REST API Using API Gateway

Basic implementation steps:

1. Open the AWS Management Console.
2. Navigate to Amazon API Gateway.
3. Select Create API.
4. Choose REST API.
5. Create a new API and provide its name.
6. Create resources such as `/customers`.
7. Add HTTP methods such as GET and POST.
8. Configure the integration endpoint (for example, AWS Lambda).
9. Configure request and response mappings if required.
10. Configure authorization and request validation.
11. Deploy the API to a stage such as `dev`.
12. Test the API using its invocation URL.

**Important:** An API must be deployed and associated with a stage before clients can invoke it.

## 6. API Integration Types

API Gateway supports different integration approaches:

- **Lambda Integration:** Invokes AWS Lambda functions to execute serverless business logic.
- **HTTP Integration:** Forwards requests to HTTP backend services.
- **AWS Service Integration:** Integrates directly with supported AWS services.
- **Mock Integration:** Returns configured responses without calling a backend.
- **Proxy Integration:** Passes requests and responses between API Gateway and the backend with minimal transformation.

Lambda proxy integration is commonly used in serverless architectures.

## 7. API Security and Access Management

API security protects backend resources from unauthorized access.

Important security mechanisms:

| Security Feature | Purpose |
|---|---|
| IAM Authorization | Controls access using AWS IAM permissions |
| Lambda Authorizer | Uses a Lambda function to authorize requests |
| Amazon Cognito | Supports user authentication and authorization |
| Resource Policies | Controls which principals or networks can invoke APIs |
| AWS WAF | Helps protect APIs against common web exploits |
| TLS/HTTPS | Encrypts data in transit |
| Request Validation | Validates incoming requests |

**Security best practices:**

- Apply least-privilege access.
- Use HTTPS for API communication.
- Validate request parameters and payloads.
- Protect sensitive information.
- Avoid storing credentials in application code.
- Enable logging and monitoring.
- Use AWS WAF where appropriate.
- Restrict access to private APIs using suitable network controls.

**Important exam concept:** API keys identify API consumers and support usage plans. They are not a substitute for authentication or authorization.

## 8. API Deployment and Stage Management

A deployment is a snapshot of an API configuration.

A stage is a named reference to a deployment.

Common stages:

- `dev` – Development environment
- `test` – Testing environment
- `prod` – Production environment

Stages support:
- Stage variables
- Request throttling
- API caching
- CloudWatch logging
- Canary deployments

**Important:** Changes to API resources, methods, integrations, and authorizers generally require redeployment to take effect.

## 9. API Throttling, Caching and Usage Plans

### Throttling
Controls request rates to help protect backend services.

API Gateway uses rate and burst targets to manage traffic.

### Caching
Stores backend responses temporarily to reduce backend requests and improve performance.

### Usage Plans and API Keys
Usage plans define which API stages and methods clients can access and can configure request-rate targets and quotas.

Example:

| Customer | Usage Plan | Request Quota |
|---|---|---|
| Basic | Basic Plan | 1,000 requests/day |
| Premium | Premium Plan | 10,000 requests/day |

These are illustrative quotas, not AWS default values.

## 10. Monitoring and Logging

Amazon API Gateway integrates with:

- Amazon CloudWatch – API metrics, logs and alarms.
- AWS CloudTrail – API Gateway management activity and API operations.
- AWS X-Ray – Distributed request tracing.

Important monitoring metrics:
- API request count
- Latency
- Integration latency
- 4XX errors
- 5XX errors

Avoid enabling full request/response data tracing in production when it may expose sensitive information.
