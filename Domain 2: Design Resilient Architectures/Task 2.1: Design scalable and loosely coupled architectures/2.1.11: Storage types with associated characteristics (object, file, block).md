
# Storage Types and Associated Characteristics (AWS)

## 1. Introduction

AWS provides three primary storage types:

1. Object Storage
2. Block Storage
3. File Storage

Each storage type has different characteristics, access methods, performance capabilities, scalability and use cases.

Selecting the correct storage type depends on application requirements, data access patterns, latency, throughput, IOPS, availability, durability and cost.

**AWS storage services should be selected based on workload requirements rather than using one storage solution for everything.**

---

## 2. Object Storage

### Definition

Object storage stores data as independent objects. Each object contains:

- Data (actual content).
- Metadata (information describing the data).
- Unique identifier (object key).

Objects are stored in buckets and accessed through APIs.

### Characteristics

- Highly scalable storage.
- High durability.
- Suitable for unstructured data.
- Accessible through HTTP/HTTPS APIs.
- Supports metadata and object versioning.
- Suitable for large-scale data storage.
- Supports lifecycle policies and storage classes.
- Does not provide traditional block-device access.
- Ideal for distributed applications and internet-accessible data.

### AWS Service: Amazon S3

Amazon Simple Storage Service (Amazon S3) is AWS's primary object storage service.

**Common use cases:**

- Backup and recovery.
- Data lakes and analytics.
- Static website hosting.
- Images, videos and documents.
- Application logs.
- Big data processing.
- Long-term data archiving.

### Important S3 Storage Classes

| Storage Class                 | Suitable For                                 |
| ----------------------------- | -------------------------------------------- |
| S3 Standard                   | Frequently accessed data                     |
| S3 Intelligent-Tiering        | Changing or unpredictable access patterns    |
| S3 Standard-IA                | Infrequently accessed data                   |
| S3 One Zone-IA                | Infrequently accessed, re-creatable data     |
| S3 Glacier Instant Retrieval  | Archive data requiring millisecond retrieval |
| S3 Glacier Flexible Retrieval | Archive data requiring minutes to hours      |
| S3 Glacier Deep Archive       | Long-term archival with hours-long retrieval |

**Key point:** Amazon S3 is designed for 99.999999999% (11 nines) durability.

## 3. Block Storage

### Definition

Block storage divides data into fixed-sized blocks. Each block is stored independently and identified by its address.

The operating system can format a block storage volume with a file system and use it like a disk.

### Characteristics

- Low-latency data access.
- High-performance input/output operations.
- Supports random read and write operations.
- Suitable for structured application data.
- Provides direct block-level access.
- Supports operating system and database storage.
- Storage capacity and performance are configurable.
- Usually attached to a compute instance or host.

### AWS Services

**A. Amazon Elastic Block Store (Amazon EBS)**

Amazon EBS provides persistent block-level storage volumes for Amazon EC2 instances.

Characteristics:

- Persistent storage independent of EC2 instance lifecycle.
- Supports multiple volume types.
- Configurable IOPS and throughput depending on volume type.
- Supports encryption.
- Supports snapshots for backup and recovery.
- Primarily designed for access by one EC2 instance at a time, although supported EBS Multi-Attach configurations exist for specific volume types and applications.

Common use cases:

- Operating system boot volumes.
- Relational databases.
- Application servers.
- Transaction processing systems.
- High-performance workloads.

**B. EC2 Instance Store**

Provides temporary block-level storage physically attached to the host machine.

Characteristics:

- Very low latency.
- High-performance temporary storage.
- Data is ephemeral.
- Data is lost when the instance is stopped, hibernated or terminated.
- Storage size depends on the EC2 instance type.

Common use cases:

- Temporary application data.
- Caches.
- Buffers.
- Temporary processing files.

**Important:** Do not use EC2 instance store as the only storage location for data that must persist.

## 4. File Storage

### Definition

File storage organizes data into a hierarchical structure using files and directories.

Users and applications access data through file-system paths.

File storage commonly uses network protocols such as:

- NFS (Network File System).
- SMB (Server Message Block).

### Characteristics

- Hierarchical file and folder structure.
- Supports shared file access.
- Provides familiar file-system interfaces.
- Multiple compute instances can access shared data.
- Supports file permissions and access controls.
- Suitable for applications requiring shared storage.
- Can support Linux and Windows environments depending on the service.

### AWS Services

**A. Amazon Elastic File System (Amazon EFS)**

Amazon EFS is a scalable, managed file storage service.

Characteristics:

- Shared file-system access.
- Supports NFS.
- Multiple EC2 instances can access the same file system.
- Automatically grows and shrinks based on stored data.
- Supports Linux-based workloads.
- Provides regional and One Zone storage options.

Common use cases:

- Shared application files.
- Web server content.
- User home directories.
- Content management systems.
- Container workloads.

**B. Amazon FSx**

Amazon FSx provides fully managed file systems for different workloads.

| FSx Service                 | Characteristics                          | Use Cases                               |
| --------------------------- | ---------------------------------------- | --------------------------------------- |
| FSx for Windows File Server | Native Windows file system and SMB       | Windows applications and shared folders |
| FSx for Lustre              | High-performance parallel file system    | HPC, machine learning and analytics     |
| FSx for NetApp ONTAP        | Enterprise file storage with NFS and SMB | Enterprise applications and migration   |
| FSx for OpenZFS             | Managed OpenZFS file system              | Linux workloads and ZFS migration       |

## 5. Comparison: Object vs Block vs File Storage

| Characteristics     | Object                          | Block                     | File                         |
| ------------------- | ------------------------------- | ------------------------- | ---------------------------- |
| Data organization   | Objects                         | Fixed-size blocks         | Files and folders            |
| Access method       | API / HTTP                      | Block device              | NFS / SMB                    |
| Structure           | Flat namespace with object keys | Address-based blocks      | Hierarchical                 |
| Performance         | Scalable data access            | Low latency and high IOPS | Shared file access           |
| Scalability         | Very high                       | Volume-based              | Managed file-system scaling  |
| Sharing             | Application/API access          | Usually host-attached     | Shared access across clients |
| Typical AWS service | Amazon S3                       | Amazon EBS                | Amazon EFS / FSx             |
| Main use cases      | Backup, media, data lakes       | Databases, OS disks       | Shared files and directories |

## 7. Important Storage Selection Factors

Before selecting an AWS storage service, evaluate:

1. **Latency:** How quickly must data be accessed?
2. **IOPS:** How many read/write operations are required per second?
3. **Throughput:** How much data must be transferred per second?
4. **Durability:** How reliably must data be preserved?
5. **Availability:** How accessible must the data remain?
6. **Scalability:** How much will the data grow?
7. **Access patterns:** Is the workload read-heavy, write-heavy, random or sequential?
8. **Sharing:** Does one instance or multiple instances need access?
9. **Cost:** What are the storage, retrieval and data transfer costs?
10. **Recovery:** What are the backup, RTO and RPO requirements?

## 8. SAA-C03 Exam Tips

- Amazon S3 = Object storage.
- Amazon EBS = Persistent block storage.
- EC2 Instance Store = Temporary block storage.
- Amazon EFS = Shared Linux file storage using NFS.
- Amazon FSx for Windows File Server = Managed Windows file storage using SMB.
- Amazon FSx for Lustre = High-performance computing and machine learning file storage.
- S3 Glacier = Long-term archival storage classes.
- EBS snapshots = Point-in-time backups stored in Amazon S3.
- Multiple EC2 instances sharing files = Consider Amazon EFS or Amazon FSx.
- Low-latency database storage = Consider Amazon EBS.
- Global access to unstructured data = Consider Amazon S3.

### Common Exam Traps

1. Do not confuse Amazon S3 with Amazon EBS. S3 is object storage; EBS is block storage.
2. Do not use EC2 Instance Store when persistent data storage is required.
3. Do not select EBS for shared file-system access when EFS or FSx is more appropriate.
4. Do not assume all Amazon FSx services support the same protocols or workloads.
5. Do not select storage based on capacity alone; consider IOPS, latency, throughput and access patterns.
