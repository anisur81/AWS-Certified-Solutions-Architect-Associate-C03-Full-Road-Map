# Sizes and Speeds Needed to Meet Business Requirements

When planning data migration or ongoing data transfers to and from Amazon Web Services (AWS), selecting the right mechanism requires analyzing your dataset size, available network bandwidth, and target completion timeframe. Selecting an improper transfer method can result in project delays, excessive network utilization, or higher operational costs.

---

## 1. Core Variables in Data Transfer Planning

To determine the appropriate AWS data transfer mechanism, three primary variables must be evaluated:

1. **Total Data Volume:** The aggregate size of the dataset to be transferred, including potential overhead for small files or encryption.
2. **Available Network Bandwidth:** The dedicated or shared network throughput allocated specifically for the transfer operation.
3. **Time Window (Service Level Agreement):** The maximum acceptable duration allowed for the transfer to complete without impacting business operations.

---

## 2. Theoretical vs. Practical Transfer Speeds

In data transfer calculations, network capacity is expressed in **bits per second** (e.g., Megabits per second [Mbps] or Gigabits per second [Gbps]), while dataset sizes are measured in **bytes** (e.g., Gigabytes [GB], Terabytes [TB], or Petabytes [PB]).

### Key Conversion Metrics
* $1 \text{ Byte (B)} = 8 \text{ bits (b)}$
* $1 \text{ Terabyte (TB)} = 1,000 \text{ Gigabytes (GB)} = 8,000,000 \text{ Megabits (Mb)}$
* $1 \text{ Tebibyte (TiB)} = 1,024 \text{ Gibibytes (GiB)}$

### Theoretical Transfer Time Formula

$$\text{Time (seconds)} = \frac{\text{Total Size in Bits}}{\text{Network Bandwidth in Bits per Second}}$$

### Accounting for Network Overhead and Efficiency
Theoretical maximum speeds are rarely achieved over WAN (Wide Area Network) connections. Real-world performance must account for network overhead:
* **TCP/IP Protocol Overhead:** Typically reduces available throughput by 10% to 20%.
* **Small File Overhead:** High file counts with small individual sizes incur metadata overhead and higher latency due to file system open/close operations.
* **Network Utilization Cap:** Online transfers generally should not exceed 80% of available link bandwidth to prevent network congestion for other enterprise services.

## 4. Selecting the Right AWS Transfer Service

AWS offers two main categories of data transfer services: **Online Transfer Services** and **Offline (Physical Device) Transfer Services**.

### Online Transfer Mechanisms

Online services are ideal for continuous ingestion, recurring sync jobs, or datasets that fit comfortably within existing network bandwidth capabilities.

#### 1. AWS Direct Connect
* **Use Case:** Dedicated private network connection from on-premises datacenters to AWS.
* **Speeds/Capacity:** Port speeds of 1 Gbps, 10 Gbps, and 100 Gbps (or sub-1 Gbps hosted connections).
* **Target Sizes:** Terabytes to Petabytes on an ongoing basis.
* **Key Advantage:** Consistent network performance with reduced data egress costs compared to internet routing.

#### 2. AWS DataSync
* **Use Case:** Automated, high-speed online data movement between on-premises storage (NFS, SMB, Object) and AWS storage services (Amazon S3, Amazon EFS, Amazon FSx).
* **Speeds/Capacity:** Utilizes custom network protocols to fully saturate available network links (up to 10 Gbps per agent).
* **Target Sizes:** Millions of files, gigabytes to hundreds of terabytes.

#### 3. Amazon S3 Transfer Acceleration
* **Use Case:** Long-distance transfer of individual files or archives directly to Amazon S3 buckets across geographically distributed locations.
* **Speeds/Capacity:** Leverages Amazon CloudFront's globally distributed edge locations to route data over the optimized AWS global network backbone.
* **Target Sizes:** Individual large files or batch uploads originating far from the target AWS Region.

#### 4. AWS Transfer Family
* **Use Case:** Secure managed file transfers over SFTP, FTPS, and FTP directly into Amazon S3 or Amazon EFS.
* **Speeds/Capacity:** Scalable, fully managed architecture bounded primarily by client bandwidth and network path limits.

---

### Offline Transfer Mechanisms (AWS Snow Family)

When dataset sizes are large or network bandwidth is constrained, physical transport using the AWS Snow Family is faster, safer, and more cost-effective than online streaming.

#### Rule of Thumb for Offline Transfers
If an online transfer is projected to take **more than 1 to 2 weeks**, physical snow appliances are generally recommended.

#### 1. AWS Snowcone
* **Capacity:** Up to 8 TB usable storage (HDD) or 14 TB (SSD).
* **Network Connectivity:** 1 GbE or 10 GbE network interfaces.
* **Target Use Case:** Edge locations, severe space/power constraints, small data collection efforts.

#### 2. AWS Snowball Edge Storage Optimized
* **Capacity:** Up to 80 TB usable block/object storage.
* **Network Connectivity:** 10/25/40/50/100 GbE connections.
* **Target Use Case:** Large-scale data migrations, local data processing, high-density edge storage.

#### 3. AWS Snowmobile
* **Capacity:** Up to 100 PB per ruggedized shipping container/truck.
* **Network Connectivity:** Dedicated high-speed network bridge supporting multi-Gbps transfer speeds locally.
* **Target Use Case:** Exabyte-scale datacenter migrations and massive archive shifts.

## 5. Decision Framework for Business Requirements

Follow this decision tree when evaluating data size and speed requirements:

1. **Calculate Available Transfer Window:**
   * Determine the target completion date for the migration or synchronization task.
2. **Measure Usable Network Throughput:**
   * Conduct baseline network tests to measure actual sustained bandwidth available to AWS endpoints during operational hours.
3. **Evaluate the 1-Week Threshold:**
   * **Under 1 Week Online:** Utilize AWS DataSync, S3 Transfer Acceleration, or Direct Connect.
   * **Over 1 to 2 Weeks Online:** Deploy AWS Snowball Edge or Snowcone to physically transfer the baseline snapshot, followed by online incremental syncs if required.
4. **Evaluate Security and Governance:**
   * Ensure end-to-end encryption requirements (AES-256) and compliance policies align with chosen physical or online transit mechanisms.

---

## 6. Summary Checklist

* Identify dataset size, file count, and available throughput.
* Apply a 20% overhead margin for TCP and small-file processing.
* Compare total estimated hours against business downtime or SLA limits.
* Select online transfer tools for continuous, lower-volume, or high-bandwidth paths.
* Select AWS Snow Family physical devices for high-volume baseline migrations over constrained network links.
