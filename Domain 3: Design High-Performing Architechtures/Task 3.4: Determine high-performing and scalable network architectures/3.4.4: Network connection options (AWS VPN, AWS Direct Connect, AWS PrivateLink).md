# Network connection options (AWS VPN, AWS Direct Connect, AWS PrivateLink)

# VPC Peering, Transit Gateway, VPN, and Direct Connect

Secure network access involves more than controlling internet connectivity. Organizations often need to connect multiple VPCs and on-premises networks.

## VPC Peering

**VPC Peering** establishes network connectivity between two VPCs using private IP addresses.

For example, an organization might have:

- One VPC for production applications.
- Another VPC for shared services.

VPC peering can allow these environments to communicate when the appropriate routes and security rules are configured.

### Security considerations

- VPC peering does not automatically permit all traffic.
- Route tables and security rules must permit the intended communication.
- Overlapping IPv4 or IPv6 address ranges can prevent peering.
- VPC peering does not provide transitive routing through a third VPC.

**Use case:** Connecting two VPCs that need a relatively straightforward private network connection.

## AWS Transit Gateway

AWS Transit Gateway acts as a central network hub that connects multiple VPCs and supported external networks.

Instead of creating a large number of individual peering connections, an organization can use Transit Gateway to simplify connectivity across many networks.

### Security benefits

- Centralizes network connectivity.
- Supports network segmentation using separate Transit Gateway route tables.
- Helps control which networks can communicate.
- Simplifies network architecture as the number of VPCs grows.

### Example

A company operates separate VPCs for development, testing, production, and shared services.

Transit Gateway can provide the connectivity architecture while routing and other security controls restrict unnecessary communication between environments.

**Important:** Centralized connectivity does not automatically mean centralized security. Routes and security policies must still be designed correctly.

## AWS Site-to-Site VPN

AWS Site-to-Site VPN creates an encrypted connection between an on-premises network and an AWS network over the internet.

It commonly uses IPsec VPN tunnels.

### Use cases

- Connecting a company office to AWS.
- Connecting an existing data center to a VPC.
- Enabling hybrid cloud applications.
- Supporting secure communication between corporate and cloud resources.

### Security considerations

Encryption protects traffic in transit, but VPN connectivity does not automatically authorize every user or device to access every cloud resource.

Routing, security groups, network ACLs, identity controls, and endpoint security remain important.

## AWS Direct Connect

AWS Direct Connect provides a dedicated network connection between an organization's network and AWS.

It can offer more predictable network performance and support private connectivity architectures.

### Security considerations

- A dedicated connection is not the same as encryption.
- Encryption requirements must be evaluated separately.
- Network routing and access controls remain necessary.
- Access to AWS services and resources must still be authorized.

### Connectivity comparison

| Service | Primary purpose | Typical use case |
|---|---|---|
| VPC Peering | Private connectivity between two VPCs | Simple VPC-to-VPC communication |
| Transit Gateway | Centralized connectivity across many networks | Enterprise network architecture |
| Site-to-Site VPN | Encrypted connectivity over the internet | Hybrid cloud connectivity |
| Direct Connect | Dedicated network connection to AWS | Enterprise connectivity with specific performance or connectivity requirements |
| PrivateLink | Private access to supported services | Service access without general network connectivity to the provider VPC |

# 3.4.4: Network Connection Options

When designing hybrid, multicloud, or inter-VPC architectures on Amazon Web Services (AWS), selecting the appropriate network connection option is essential for ensuring security, performance, reliability, and cost-efficiency. AWS provides several native networking solutions tailored to different connectivity scenarios, security requirements, and bandwidth needs. 

This section covers the three primary connection services:
1. **AWS Virtual Private Network (AWS VPN)**
2. **AWS Direct Connect (DX)**
3. **AWS PrivateLink**

---

## 1. AWS Virtual Private Network (AWS VPN)

AWS VPN establishes secure, encrypted connections between your on-premises networks, remote offices, mobile devices, and the AWS Cloud. AWS VPN leverages standard IP Security (IPsec) protocols to encrypt data in transit over the public internet.

```
+---------------------+       (IPsec Tunnel over Internet)       +---------------------+
| On-Premises Network | <======================================> |      AWS Cloud      |
|  (Customer Gateway) |                                          |  (Virtual Private Gateway / |
+---------------------+                                          |    Transit Gateway) |
                                                                 +---------------------+
```

### 1.1 AWS Site-to-Site VPN
AWS Site-to-Site VPN connects an on-premises network (or data center) securely to an AWS Virtual Private Cloud (VPC) or an AWS Transit Gateway.

* **Key Components:**
  * **Virtual Private Gateway (VGW):** The VPN concentrator on the AWS side attached to a single VPC.
  * **Transit Gateway (TGW):** A centralized hub connecting multiple VPCs and on-premises networks through a single VPN attachment.
  * **Customer Gateway (CGW):** The physical appliance or software application on your side of the Site-to-Site VPN connection.
  * **Customer Gateway Device:** The physical/virtual device in your data center configured to establish the IPsec connection.

* **Tunnel Architecture:**
  * Each AWS Site-to-Site VPN connection automatically consists of **two parallel IPsec tunnels** terminating on different AWS Availability Zones for high availability.
  * Supports both **Static Routing** and **Dynamic Routing (via BGP - Border Gateway Protocol)**. BGP is recommended for automatic failover and path selection.

* **Use Cases:**
  * Quick setup for hybrid network connectivity.
  * Secure, low-to-moderate bandwidth connection over the public internet.
  * Backup connectivity option for AWS Direct Connect.

### 1.2 AWS Client VPN
AWS Client VPN is a managed remote access VPN solution that enables users to securely access AWS resources or on-premises networks from anywhere using OpenVPN-compatible clients.

* **Key Features:**
  * High scalability, automatically adjusting to the number of remote users.
  * Authentication options include Active Directory, SAML 2.0 (SSO), and mutual certificate authentication.
  * Fine-grained authorization rules based on Active Directory groups or user identities.

## 2. AWS Direct Connect (DX)

AWS Direct Connect bypasses the public internet to establish a dedicated, private physical network connection from an on-premises data center, co-location facility, or office directly to AWS.

```
+------------------+         Cross-Connect          +------------------+     AWS Backbone     +------------------+
| Customer Network | <============================> | Direct Connect   | <==================> |    AWS Cloud     |
|   (On-Premises)  |  (Dedicated/Hosted Fiber)      | Location (Port)  |                      |   (VPCs / S3)    |
+------------------+                                +------------------+                      +------------------+
```

### 2.1 Connection Types
* **Dedicated Connections:** A physical Ethernet connection allocated exclusively to a single customer.
  * Available capacities: **1 Gbps, 10 Gbps, 100 Gbps, and 400 Gbps**.
  * Provisioned directly through the AWS Management Console and cross-connected at a Direct Connect location.
* **Hosted Connections:** Provisioned through an AWS Direct Connect Partner.
  * Capacities range from **50 Mbps to 10 Gbps**.
  * Dedicated physical links are shared at the partner level, but network traffic is logically isolated.

### 2.2 Virtual Interfaces (VIFs)
Traffic over a Direct Connect link is routed using Virtual Interfaces (VIFs), each mapped to an 802.1q VLAN:
1. **Private VIF:** Connects to a single VPC via a Virtual Private Gateway (VGW) using private IP addresses.
2. **Public VIF:** Accesses public AWS services (such as Amazon S3, DynamoDB, and public endpoints) using public IP addresses without traversing the public internet.
3. **Transit VIF:** Connects to an AWS Transit Gateway, enabling connectivity to hundreds of VPCs over a single Direct Connect connection.

### 2.3 Direct Connect Gateway (DXGW)
A Direct Connect Gateway is a globally available resource that allows you to connect a single Direct Connect connection (via Private or Transit VIFs) to VPCs or Transit Gateways located across multiple AWS Regions.

### 2.4 Use Cases
* High-throughput applications requiring low and consistent latency (e.g., real-time analytics, database replication).
* Large-scale data migration projects.
* Regulatory or compliance requirements necessitating private network transport (non-internet routing).

## 3. AWS PrivateLink

AWS PrivateLink provides private, secure connectivity between VPCs, AWS services, and on-premises applications without exposing traffic to the public internet. Unlike VPC Peering or Transit Gateway connections, PrivateLink does not require complex routing tables, Internet Gateways, or IP address space overlap management.

```
+--------------------+        AWS Private Backbone        +--------------------+
| Consumer VPC       | =================================> | Provider VPC /     |
| (Interface Endpoint|      (Unidirectional Access)       | AWS Service        |
|  with ENI)         |                                    | (Network LB)       |
+--------------------+                                    +--------------------+
```

### 3.1 Key Architectural Concepts
* **Interface VPC Endpoints:** An elastic network interface (ENI) with a private IP address from your subnet's IP range that serves as an entry point for traffic destined for an endpoint service.
* **Endpoint Services:** Services hosted by AWS (e.g., S3, DynamoDB, EC2 API), AWS Marketplace partners, or custom applications hosted in another VPC behind a **Network Load Balancer (NLB)**.
* **Unidirectional Connectivity:** Traffic can only be initiated by the consumer of the endpoint; the provider service cannot initiate connections back to the consumer VPC.

### 3.2 Benefits of AWS PrivateLink
* **No IP Overlap Issues:** Enables communication between networks with overlapping CIDR blocks, as traffic is proxied via Network Address Translation (NAT) at the endpoint interface.
* **Security & Compliance:** Traffic remains entirely within the AWS global network backbone, isolating data from the public internet.
* **Scalable SaaS Delivery:** Simplifies exposing internal microservices or SaaS applications to thousands of customer VPCs securely.

## 4. Architectural Comparison & Decision Matrix

| Feature | AWS Site-to-Site VPN | AWS Direct Connect | AWS PrivateLink |
| :--- | :--- | :--- | :--- |
| **Transport Medium** | Public Internet (Encrypted) | Dedicated / Shared Physical Link | AWS Internal Global Network |
| **Setup Time** | Minutes to Hours | Days to Weeks | Minutes |
| **Data Transfer Cost** | Low setup cost; standard internet egress rates | Lower per-GB data egress rates; port hour fees | Per-GB data processing fees; endpoint hour fees |
| **Bandwidth Limits** | Up to 1.25 Gbps per tunnel | Up to 100 Gbps / 400 Gbps | Automatically scales per ENI |
| **Latency & Jitter** | Variable (dependent on public internet) | Extremely Low & Consistent | Lowest (internal AWS network) |
| **Primary Focus** | Secure hybrid baseline / backup | High-volume continuous hybrid link | Targeted microservice / SaaS consumption |

## 5. Resiliency and Hybrid Patterns

### 5.1 High Availability Direct Connect + VPN Backup
For mission-critical workloads, organizations often combine AWS Direct Connect with an AWS Site-to-Site VPN connection. Direct Connect acts as the primary path due to its low latency and high bandwidth, while the VPN connection serves as an automated failover path over the internet using dynamic BGP routing.

### 5.2 Direct Connect + MACsec / IPsec
For maximum security over dedicated physical infrastructure:
* **MACsec (802.1AE):** Provides layer 2 hardware encryption directly over 10 Gbps, 100 Gbps, and 400 Gbps Direct Connect links.
* **VPN over Direct Connect:** Standard IPsec VPN tunnels can be established over a Public or Private VIF on Direct Connect for layer 3 end-to-end encryption.
