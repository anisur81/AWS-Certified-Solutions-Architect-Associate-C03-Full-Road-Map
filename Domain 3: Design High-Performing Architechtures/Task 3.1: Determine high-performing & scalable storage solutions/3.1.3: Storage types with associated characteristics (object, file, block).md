# AWS Storage Types and Associated Characteristics

## 1. Introduction

AWS provides three primary storage types:

1. **Object Storage**
2. **File Storage**
3. **Block Storage**

Each storage type has different characteristics, access methods, performance capabilities, scalability, and use cases.

Selecting the appropriate storage type depends on application requirements, data access patterns, latency, throughput, IOPS, durability, availability, and cost.

---

## 2. Object Storage

### Definition

Object storage stores data as independent objects rather than files or blocks. Each object contains:

- **Data:** Actual content, such as images, videos, documents, and backups.
- **Metadata:** Information describing the object.
- **Unique Identifier (Key):** Used to identify and retrieve the object.

Objects are stored inside containers called buckets.

### AWS Services

- Amazon Simple Storage Service (Amazon S3)
- Amazon S3 Glacier storage classes
- Amazon S3 Express One Zone

### Key Characteristics

| Characteristic    | Description                                                         |
| ----------------- | ------------------------------------------------------------------- |
| Data structure    | Objects containing data and metadata                                |
| Access method     | HTTP/HTTPS APIs                                                     |
| Scalability       | Virtually unlimited scalability                                     |
| Durability        | Amazon S3 Standard is designed for 99.999999999% durability         |
| Performance       | Suitable for large-scale data storage and retrieval                 |
| Metadata          | Supports custom and system-defined metadata                         |
| Accessibility     | Accessible through AWS services and authorized internet connections |
| Cost              | Multiple storage classes based on access patterns                   |
| Data organization | Buckets and object keys                                             |

### Common Use Cases

- Backup and disaster recovery.
- Static website hosting.
- Data lakes and big data analytics.
- Images, videos, and document storage.
- Log storage.
- Long-term data archiving.
- Application-generated content.

### Advantages

- Highly scalable.
- High durability.
- Cost-effective for large datasets.
- Supports lifecycle management.
- Supports versioning and encryption.
- Suitable for unstructured data.

### Limitations

- Not designed to behave like a traditional block device.
- Does not provide native POSIX file-system access.
- Object updates generally involve replacing the object rather than modifying individual blocks.

## 3. File Storage

### Definition

File storage organizes data into a hierarchical structure using files and directories (folders).

Applications and users access data through a shared file system using standard file-system protocols.

Common protocols include:

- NFS (Network File System).
- SMB (Server Message Block).

### AWS Services

- Amazon Elastic File System (Amazon EFS).
- Amazon FSx for Windows File Server.
- Amazon FSx for Lustre.
- Amazon FSx for NetApp ONTAP.
- Amazon FSx for OpenZFS.

### Key Characteristics

| Characteristic | Description                                           |
| -------------- | ----------------------------------------------------- |
| Data structure | Files and directories                                 |
| Access method  | NFS and SMB protocols                                 |
| Scalability    | Depends on the AWS file storage service               |
| Sharing        | Supports shared access by multiple clients            |
| Management     | Hierarchical directory structure                      |
| Accessibility  | Network-based file-system access                      |
| Performance    | Depends on throughput, IOPS, and latency requirements |
| Use case       | Shared application and user data                      |

### Amazon EFS Characteristics

- Fully managed elastic file storage.
- Primarily designed for Linux workloads.
- Supports NFS access.
- Can be mounted by multiple EC2 instances simultaneously.
- Automatically scales storage capacity.
- Supports regional and One Zone storage classes.

### Amazon FSx Characteristics

Amazon FSx provides fully managed file systems for different workloads.

| FSx Service                 | Main Purpose                                                      |
| --------------------------- | ----------------------------------------------------------------- |
| FSx for Windows File Server | Windows-based applications and SMB file sharing                   |
| FSx for Lustre              | High-performance computing (HPC), machine learning, and analytics |
| FSx for NetApp ONTAP        | Enterprise file storage and advanced data management              |
| FSx for OpenZFS             | Applications requiring OpenZFS file-system capabilities           |

### Common Use Cases

- Shared application files.
- Enterprise file servers.
- Home directories.
- Content management systems.
- Media processing.
- Application development environments.
- Machine learning and analytics workloads.

### Advantages

- Supports shared file access.
- Provides familiar file-system interfaces.
- Organizes data using directories and files.
- Supports multiple compute instances accessing shared data.
- Reduces the need to manage individual file servers.

### Limitations

- Performance depends on the selected file system and configuration.
- Network connectivity is required for network-based access.
- Cost and scalability characteristics vary between services.

## 4. Block Storage

### Definition

Block storage divides data into fixed-sized blocks. Each block has a unique address, and the operating system or application manages how blocks are organized into files and file systems.

Block storage is suitable for workloads requiring low latency and high-performance storage.

### AWS Services

- Amazon Elastic Block Store (Amazon EBS).
- Amazon EC2 Instance Store.

### Key Characteristics

| Characteristic | Description                                                      |
| -------------- | ---------------------------------------------------------------- |
| Data structure | Fixed-sized blocks                                               |
| Access method  | Block-level access                                               |
| Performance    | High performance and low latency                                 |
| IOPS           | Supports high input/output operations per second                 |
| Scalability    | Capacity and performance depend on volume type and configuration |
| Management     | Operating system manages file systems                            |
| Persistence    | Depends on the storage service                                   |
| Use case       | Databases and transactional applications                         |

### Amazon EBS Characteristics

- Provides persistent block-level storage.
- Can be attached to EC2 instances.
- Supports SSD and HDD volume types.
- Supports encryption.
- Supports snapshots for backup and recovery.
- Offers configurable storage capacity and performance.
- EBS volumes persist independently of the associated EC2 instance.

**Common EBS volume types:**

| Volume Type                     | Description                                          |
| ------------------------------- | ---------------------------------------------------- |
| General Purpose SSD (gp3, gp2)  | General-purpose workloads                            |
| Provisioned IOPS SSD (io2, io1) | I/O-intensive and mission-critical workloads         |
| Throughput Optimized HDD (st1)  | Frequently accessed, throughput-intensive workloads  |
| Cold HDD (sc1)                  | Infrequently accessed, throughput-oriented workloads |

### EC2 Instance Store Characteristics

- Provides temporary block-level storage.
- Physically attached to the host computer.
- Offers very high I/O performance for suitable instance types.
- Data is not persistent across instance stop, hibernation, or termination.
- Suitable for temporary data, caches, and buffers.

### Common Use Cases

- Relational databases.
- NoSQL databases.
- Operating system boot volumes.
- Enterprise applications.
- Transaction processing systems.
- Applications requiring low-latency storage.

### Advantages

- High-performance storage.
- Low-latency data access.
- Suitable for random read/write operations.
- Supports database workloads.
- EBS provides persistent storage and snapshots.

### Limitations

- EBS capacity and performance require configuration and monitoring.
- Most EBS volume types are attached to a single EC2 instance at a time.
- Instance Store data is temporary and requires separate data protection.

## 6. How to Choose the Right Storage Type

Choose the storage type based on application requirements:

| Requirement                             | Recommended AWS Service            |
| --------------------------------------- | ---------------------------------- |
| Store images, videos, and documents     | Amazon S3                          |
| Static website hosting                  | Amazon S3                          |
| Long-term data archiving                | S3 Glacier storage classes         |
| Shared Linux file storage               | Amazon EFS                         |
| Windows shared file storage             | Amazon FSx for Windows File Server |
| High-performance computing file storage | Amazon FSx for Lustre              |
| Database storage                        | Amazon EBS                         |
| EC2 operating system disk               | Amazon EBS                         |
| Temporary high-performance storage      | EC2 Instance Store                 |

## 7. SAA-C03 Exam Tips

Remember these important differences:

1. **Amazon S3 = Object Storage:** Use it for backups, static websites, data lakes, images, and videos.
2. **Amazon EFS = File Storage:** Use it when multiple Linux EC2 instances need simultaneous shared file access.
3. **Amazon FSx = Managed File Systems:** Select the appropriate FSx service based on Windows, Lustre, NetApp ONTAP, or OpenZFS requirements.
4. **Amazon EBS = Block Storage:** Use it for EC2 boot volumes, databases, and applications requiring persistent, low-latency storage.
5. **EC2 Instance Store = Temporary Block Storage:** Use it for caches, buffers, and temporary data that can be recreated.
6. **S3 Glacier = Archival Storage:** Use it for long-term data retention with retrieval times depending on the selected storage class.
7. **Shared Storage:** When multiple EC2 instances require access to the same file system, consider Amazon EFS or Amazon FSx.
8. **Database Performance:** For applications requiring high IOPS and low latency, consider appropriately configured EBS SSD volumes.
