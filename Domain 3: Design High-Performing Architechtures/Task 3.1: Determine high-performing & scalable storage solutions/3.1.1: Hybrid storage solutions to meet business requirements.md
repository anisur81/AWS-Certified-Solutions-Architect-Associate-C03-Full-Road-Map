# Hybrid Storage Solutions to Meet Business Requirements

> **AWS Cloud / Solutions Architect Study Notes**  
> Focus: selecting and combining on-premises and AWS storage services to satisfy performance, latency, compliance, availability, scalability, and cost requirements.

## 1. What Is Hybrid Storage?

Hybrid storage combines an organization's on-premises storage infrastructure with AWS cloud storage. Applications can continue using local storage where necessary while data is moved, replicated, cached, or backed up to AWS.

A hybrid design is useful when a business cannot move everything to the cloud at once, needs low-latency local access, has data-residency obligations, wants cloud-based backup and disaster recovery (DR), or needs to expand storage capacity without buying more hardware.

**Typical objectives**

- Keep frequently accessed data close to on-premises applications.
- Extend on-premises capacity with scalable AWS storage.
- Back up or replicate data to AWS for DR.
- Migrate data gradually with minimal disruption.
- Reduce capital expenditure and operational overhead.
- Apply security, retention, and lifecycle policies consistently.

## 2. Main AWS Hybrid Storage Services

### 2.1 AWS Storage Gateway

AWS Storage Gateway connects on-premises applications to AWS storage through familiar storage protocols. It is commonly used for hybrid access, cloud backup, and gradual migration.

| Gateway type | How it works | Typical business requirement |
|---|---|---|
| **Amazon S3 File Gateway** | Provides an on-premises file interface using NFS or SMB. Files are stored as objects in Amazon S3, with a local cache for frequently accessed data. | Existing file-based applications need local access while data is stored durably in S3. |
| **Volume Gateway – Cached volumes** | Keeps primary data in Amazon S3 and maintains frequently accessed data locally in a cache. Presents storage to applications as iSCSI block volumes. | Expand storage capacity while retaining low-latency access to frequently used blocks. |
| **Volume Gateway – Stored volumes** | Keeps the full dataset on premises and asynchronously backs up point-in-time snapshots to AWS. | Applications require complete local datasets, but the business also needs off-site backups and DR. |
| **Tape Gateway** | Presents a virtual tape library (VTL) to existing backup applications; virtual tapes are stored in AWS, commonly using S3 Glacier storage classes for archive. | Replace or reduce physical tape infrastructure while retaining tape-based backup workflows. |

**Selection tip:** Choose File Gateway for file access, Volume Gateway for iSCSI block storage, and Tape Gateway when existing backup software depends on virtual tape workflows.

### 2.2 AWS DataSync

AWS DataSync is an online data-transfer service for moving data between on-premises storage and AWS storage, and between supported AWS storage services.

- Supports common file protocols such as NFS and SMB, plus other supported source and destination locations.
- Automates and schedules transfers.
- Can perform recurring transfers for ongoing synchronization.
- Helps validate data integrity and encrypt data in transit.
- Common destinations include Amazon S3, Amazon EFS, and Amazon FSx.

**Use case:** A company needs to copy several terabytes from an on-premises NAS to Amazon S3, then run scheduled incremental transfers to keep the cloud copy updated.

**Important:** DataSync moves data; it does not provide the same continuously mounted, cloud-backed file interface as Storage Gateway.

### 2.3 AWS Transfer Family

AWS Transfer Family provides managed file-transfer endpoints for moving files into and out of AWS storage.

- Supports SFTP, FTPS, and FTP; AS2 is also available for supported business-to-business workflows.
- Can use Amazon S3 or Amazon EFS as the storage backend.
- Helps businesses retain familiar transfer protocols without operating their own file-transfer servers.

**Use case:** A bank's partners send files through SFTP, and the files must land directly in an S3 bucket for processing.

### 2.4 AWS Direct Connect and VPN

Hybrid storage depends on reliable connectivity between the data center and AWS.

- **AWS Direct Connect:** Provides dedicated network connectivity from an organization's premises to AWS. It can offer more consistent network performance than internet-based connectivity, depending on the circuit and design.
- **AWS Site-to-Site VPN:** Establishes encrypted IPsec tunnels over the internet between the on-premises network and an Amazon VPC.

These are connectivity options, not storage services. Select them based on bandwidth, latency, resilience, security, and cost requirements.

### 2.5 AWS Outposts

AWS Outposts brings supported AWS infrastructure and services to an on-premises facility or colocation site. It is appropriate when workloads need to run close to local users or systems, or when local data processing and residency requirements make a fully remote cloud deployment unsuitable.

Outposts is not simply a file-transfer tool. It extends AWS infrastructure and operating experience to the customer's location. Confirm service, hardware, facility, and regional availability before designing around it.

## 3. Matching Business Requirements to a Solution

| Business requirement | Suitable AWS approach |
|---|---|
| On-premises applications need file access backed by cloud object storage | Amazon S3 File Gateway |
| Local applications need iSCSI block storage with cloud-backed capacity | Volume Gateway – Cached volumes |
| Full dataset must remain local, with cloud snapshots for backup | Volume Gateway – Stored volumes |
| Existing backup system uses tape workflows | Tape Gateway |
| Large or recurring online file transfers to AWS | AWS DataSync |
| Partners require SFTP/FTPS/FTP file exchange | AWS Transfer Family |
| Dedicated, predictable connectivity is required | AWS Direct Connect |
| Encrypted connectivity over the internet is sufficient | AWS Site-to-Site VPN |
| AWS infrastructure must run at an on-premises location | AWS Outposts |

## 4. Example Hybrid Storage Architecture

**Scenario:** A company runs a business application in its data center. Employees access shared files locally, but the company wants scalable cloud storage, off-site backup, and a path to cloud analytics.

```text
On-premises data center
+--------------------------------------+
| Business application                 |
|          |                           |
|          v                           |
| S3 File Gateway / local cache        |
|          |                           |
|          +------ secure network -----+------> Amazon S3
|                                               |
| On-premises NAS -- AWS DataSync --------------+
|                                               |
| Backup application -- Tape Gateway ----------> S3 / S3 Glacier
+-----------------------------------------------+
                                                |
                                      Analytics / DR / Archive
```

**How it works**

1. The application accesses files through the File Gateway using supported file protocols.
2. Frequently accessed files can be served from the local cache; file data is stored in Amazon S3.
3. DataSync transfers existing NAS data and can run scheduled transfers for updates.
4. Tape Gateway allows compatible backup software to write to virtual tapes stored in AWS.
5. AWS services can use the cloud data for analytics, retention, and recovery workflows.

The exact design depends on application consistency, cache sizing, network capacity, recovery objectives, and supported gateway configurations.

## 5. Key Design Considerations

### Performance and latency
- Keep latency-sensitive workloads close to their users and applications.
- Size local caches based on the active working set, not total dataset size.
- Estimate transfer time using data volume, available bandwidth, protocol overhead, and change rate.
- Consider Direct Connect for sustained high-volume connectivity; retain resilient network paths.

### Availability and disaster recovery
- Define **RPO** (maximum acceptable data loss) and **RTO** (target recovery time).
- Decide how often data must be transferred or snapshots created.
- Test restoration and application recovery; a successful backup alone does not prove recoverability.
- Design for gateway, network, on-premises, and AWS service failures.

### Security and compliance
- Encrypt data in transit and at rest.
- Use IAM policies and resource policies with least privilege.
- Apply AWS KMS keys where supported and required.
- Restrict network access and protect transfer endpoints.
- Define data classification, retention, deletion, and audit requirements.
- Confirm whether data must remain in a particular country or facility.

### Cost optimization
- Compare local hardware, gateway infrastructure, AWS storage, requests, data transfer, and connectivity costs.
- Use appropriate S3 storage classes and lifecycle policies for data access patterns.
- Avoid retaining unnecessary duplicate copies.
- Monitor cache utilization, storage growth, and transfer activity.

## 6. Online vs. Offline Data Migration

| Method | Best suited for | Main consideration |
|---|---|---|
| **Online transfer** (for example, DataSync or Transfer Family) | Frequent updates, ongoing synchronization, and time-sensitive migration | Requires sufficient network bandwidth; schedule transfers to reduce business impact. |
| **Offline / physical transfer** | Very large one-time transfers, limited bandwidth, or situations where data can be static during transit | Physical transfer takes planning and transit time. Check current AWS service availability and eligibility. |

**Current documentation note:** AWS's current storage decision guide states that the Snow Family is no longer available to new customers; existing customers with active Snow jobs are unaffected. Do not assume Snow devices are available for a new project—check the latest AWS guidance and alternatives.

## 7. Exam Tips and Common Confusions

- **File Gateway = file access** using NFS/SMB with Amazon S3-backed storage.
- **Volume Gateway = block access** through iSCSI.
- **Tape Gateway = virtual tape** for existing backup workflows.
- **DataSync = automated data movement**, not a persistent file-system gateway.
- **Transfer Family = managed file-transfer protocols** such as SFTP, FTPS, and FTP.
- **Direct Connect/VPN = network connectivity**, not storage.
- **Outposts = AWS infrastructure on premises**, for local processing and low-latency requirements.
- Choose based on access pattern, latency, protocol, data location, recovery objectives, security, and total cost—not simply on storage capacity.

## 8. Quick Knowledge Check

1. An on-premises application requires SMB access to files stored in Amazon S3. Which service should you consider?  
   **Answer:** Amazon S3 File Gateway.

2. A company needs to transfer data from an NFS NAS to Amazon S3 every night. Which service is suitable?  
   **Answer:** AWS DataSync.

3. A partner requires SFTP to upload files directly into an S3 bucket. Which service is suitable?  
   **Answer:** AWS Transfer Family.

4. An application requires iSCSI block storage, with primary data held in AWS and frequently accessed data cached locally. Which option fits?  
   **Answer:** Volume Gateway – Cached volumes.

5. A company needs a dedicated private network connection from its data center to AWS. Which service should it evaluate?  
   **Answer:** AWS Direct Connect.
