# Storage services with appropriate use cases (Amazon S3, Amazon EFS, Amazon EBS)

## Overview

AWS provides different storage services to meet application requirements for performance, scalability, durability, access method, and cost. The
three fundamental storage models are:

-   **Object storage** -- stores data as objects in buckets. Best for     unstructured data accessed through APIs.
-   **File storage** -- stores data in a hierarchical file system. Best     when applications need shared file access using standard file
    protocols.
-   **Block storage** -- provides raw storage volumes that operating     systems use like hard drives. Best for operating systems, databases,
    and applications requiring low-latency disk I/O.

The key services in this topic are **Amazon S3 (object)**, **Amazon EFS (file)**, and **Amazon EBS (block)**.

## 1. Amazon Simple Storage Service (Amazon S3)

### What it is

Amazon S3 is a scalable object storage service. Data is stored as **objects** inside **buckets**. Each object consists of the data,
metadata, and a unique key (object name) within its bucket.

Applications typically access S3 through AWS APIs, SDKs, the AWS CLI, or HTTP-based interfaces. S3 is not a traditional mounted block disk or
shared POSIX file system.

### Appropriate use cases

-   **Backup and restore:** Store application backups, database exports,    and recovery data.
-   **Static website hosting:** Store website assets such as HTML, CSS,    JavaScript, and images.
-   **Data lakes and analytics:** Store large datasets, logs, and files   for analytics services.
-   **Media and content distribution:** Store images, videos, documents,     and downloadable content.
-   **Archiving:** Retain long-term data using lower-cost S3 Glacier     storage classes.
-   **Application data:** Store user uploads, reports, and documents     independently of compute instances.

### Important S3 features

-   **Storage classes:** Select a class based on access frequency,     retrieval needs, and cost.
    -   `S3 Standard` -- frequently accessed data.
    -   `S3 Intelligent-Tiering` -- data with unknown or changing access         patterns.
    -   `S3 Standard-IA` -- long-lived, infrequently accessed data that         still needs rapid retrieval.
    -   `S3 One Zone-IA` -- infrequently accessed, recreatable data         where single-AZ storage is acceptable.
    -   `S3 Glacier Instant Retrieval` -- rarely accessed archive data         requiring millisecond retrieval.
    -   `S3 Glacier Flexible Retrieval` -- archive data that can         tolerate retrieval delays.
    -   `S3 Glacier Deep Archive` -- long-term data that is very rarely         accessed.
-   **Versioning:** Keep multiple versions of objects to help recover     from accidental overwrites or deletions.
-   **Lifecycle policies:** Automatically transition objects between     storage classes or expire objects.
-   **Replication:** Copy objects to buckets in the same or another AWS     Region, depending on the replication configuration.
-   **Security:** Use IAM policies, bucket policies, encryption, and S3     Block Public Access controls.
-   **Object Lock:** Help prevent objects from being deleted or     overwritten for a defined retention period or indefinitely.

### Example

A company runs a web application on EC2. Users upload profile photos and PDF documents. The application stores these objects in an S3 bucket
rather than on the EC2 instance's local disk. If an instance is replaced, the uploaded files remain in S3.

## 2. Amazon Elastic File System (Amazon EFS)

### What it is

Amazon EFS is a fully elastic, managed file storage service for
Linux-based workloads. It supports the Network File System protocol
(NFSv4.0 and NFSv4.1), allowing supported compute resources to mount a
shared file system.

EFS automatically grows and shrinks as files are added or removed.
Multiple clients can access the same file system, subject to network and
file-system permissions.

### Appropriate use cases

-   **Shared application files:** Multiple EC2 instances need access to
    the same files.
-   **Web server clusters:** Several web servers in an Auto Scaling
    group share website content or uploaded files.
-   **Content management systems:** Applications require a common file
    repository.
-   **Home directories:** Provide persistent shared home directories for
    users.
-   **Container workloads:** Share persistent file data across supported
    ECS or EKS workloads.
-   **Development and analytics:** Share common datasets between
    multiple compute resources.

### Important EFS features

-   **Shared access:** Multiple clients can mount and access the same
    file system.
-   **Elastic capacity:** Storage capacity scales automatically;
    capacity does not need to be pre-provisioned.
-   **Regional file systems:** Store data redundantly across multiple
    Availability Zones in an AWS Region. This is the recommended option
    for workloads requiring multi-AZ availability.
-   **One Zone file systems:** Store data in a single Availability Zone
    and can be appropriate when the workload accepts the associated
    availability and data-loss risk.
-   **Performance and throughput modes:** Choose settings appropriate
    for workload latency and throughput requirements. Elastic throughput
    can scale with workload activity.
-   **Security:** Control network access with security groups and use
    IAM authorization and POSIX permissions. EFS supports encryption at
    rest and in transit.

### Example

A company deploys an application on three EC2 instances behind an
Application Load Balancer. All three instances need to read and write
the same uploaded documents. Mounting one EFS file system on the
instances provides shared file access.

## 3. Amazon Elastic Block Store (Amazon EBS)

### What it is

Amazon EBS provides persistent, block-level storage volumes for use with
EC2 instances. An EBS volume behaves like a hard drive attached to a
server. The operating system can format it with a file system and use it
for application files, operating system data, or databases.

An EBS volume exists independently of the running life of its EC2
instance, although it is associated with an Availability Zone. The
volume and the EC2 instance must be in the same Availability Zone when
attaching a standard EBS volume.

### Appropriate use cases

-   **EC2 boot volumes:** Store an instance's operating system.
-   **Databases:** Store database data files and transaction logs that
    require persistent, low-latency block storage.
-   **Enterprise applications:** Provide persistent disk storage for
    applications running on EC2.
-   **Transactional workloads:** Use SSD-backed volumes for workloads
    requiring frequent, low-latency reads and writes.
-   **Throughput-intensive workloads:** Use suitable HDD-backed volumes
    for workloads that process large amounts of sequential data.

### Important EBS features

-   **Volume types:** Different volume types provide different
    performance and cost characteristics.
    -   `gp3` / `gp2` -- General Purpose SSD for a broad range of
        workloads.
    -   `io2` / `io1` -- Provisioned IOPS SSD for I/O-intensive
        applications that need high, consistent performance.
    -   `st1` -- Throughput Optimized HDD for frequently accessed,
        throughput-intensive workloads.
    -   `sc1` -- Cold HDD for less frequently accessed,
        throughput-oriented workloads.
-   **Persistence:** EBS volumes can persist beyond the life of an EC2
    instance, depending on volume and instance termination settings.
-   **Snapshots:** Create point-in-time backups of EBS volumes.
    Snapshots can be used to restore volumes and support migration
    across Availability Zones or Regions.
-   **Encryption:** Encrypt EBS volumes and their snapshots.
-   **Elastic Volumes:** For supported volume and instance
    configurations, modify volume size, type, and performance without
    detaching the volume.

### Example

A production EC2 instance runs a PostgreSQL database. The database
stores its data files on an EBS SSD volume. The volume provides
persistent block storage, and scheduled EBS snapshots provide a
point-in-time backup mechanism.

## 5. How to Choose the Right Service

Use the access pattern to make the decision:

-   **Choose S3** when you need to store and retrieve objects such as
    images, videos, backups, logs, documents, or data lake files through
    APIs.
-   **Choose EFS** when multiple EC2 instances or supported compute
    services need concurrent access to the same shared file system.
-   **Choose EBS** when an EC2 instance needs a persistent disk for its
    operating system, database, or application that performs block-level
    I/O.

## 6. Exam Tips

-   **S3 = Object storage.** Think buckets, objects, API access,
    lifecycle policies, versioning, replication, and archival.
-   **EFS = Shared file storage.** Think NFS, Linux workloads, automatic
    capacity scaling, and multiple EC2 instances accessing the same
    files.
-   **EBS = Block storage.** Think EC2 disks, boot volumes, databases,
    SSD/HDD volume types, and snapshots.
-   If a question says **multiple EC2 instances must access the same
    shared files**, consider EFS.
-   If it says **an EC2 database needs persistent, low-latency disk
    storage**, consider EBS.
-   If it says **store objects, backups, static content, or a data
    lake**, consider S3.
-   Do not confuse **EBS snapshots** with EFS or S3 as the primary
    application storage interface. EBS snapshots are backup artifacts
    for EBS volumes.
