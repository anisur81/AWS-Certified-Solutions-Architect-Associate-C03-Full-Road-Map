# Task 1.1: Design secure access to AWS resources

## 1. Learning Objectives

By the end of this lesson, you should be able to:

- Explain why organizations use multiple AWS accounts.
- Manage accounts centrally using AWS Organizations.
- Apply centralized permissions with AWS IAM Identity Center.
- Use IAM roles and cross-account access safely.
- Apply least-privilege access and multi-factor authentication (MFA).
- Understand Service Control Policies (SCPs).
- Test access permissions and troubleshoot common errors.

## 2. Typical Multi-Account AWS Environment

A typical multi-account AWS environment separates workloads and security responsibilities into different accounts.

| AWS Account | Purpose |
|---|---|
| **Management** | Manages the AWS Organization and consolidated billing. |
| **Production** | Hosts live applications and production data. |
| **Development** | Used for testing and development. |
| **Security** | Centralizes security operations and investigations. |
| **Log Archive** | Stores centralized audit and security logs. |

### Why Separate Accounts?

- **Isolation:** A compromised development account does not automatically grant access to production.
- **Access control:** Give teams access only to the accounts and resources they need.
- **Billing:** Track costs separately by account.
- **Governance:** Apply organization-wide guardrails.
- **Auditing:** Collect and investigate activity across accounts.

## 3. Understand the Main Access Controls

| Control | What It Does |
|---|---|
| **IAM policy** | Grants or denies actions for an identity, subject to other applicable controls. |
| **IAM role** | Provides a set of permissions that an authorized principal can assume. |
| **Trust policy** | Specifies who or what can assume a role. |
| **Permission set** | Defines the permissions IAM Identity Center provisions for account access. |
| **Service Control Policy (SCP)** | Sets the maximum available permissions for identities in member accounts; it does not grant permissions by itself. |
| **Resource policy** | Controls access directly on supported resources, such as an Amazon S3 bucket. |
