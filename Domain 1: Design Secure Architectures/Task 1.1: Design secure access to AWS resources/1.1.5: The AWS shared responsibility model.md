# 1.1.5: The AWS shared responsibility model

  
## 1. Introduction
The **AWS Shared Responsibility Model** defines the security responsibilities shared between Amazon Web Services (AWS) and its customers.

AWS is responsible for securing the underlying cloud infrastructure, while customers are responsible for securing the resources, applications, and data they deploy in the cloud.

It is commonly explained as:

- **Security of the Cloud:** AWS responsibility.
- **Security in the Cloud:** Customer responsibility.

## 2. AWS Responsibilities – Security of the Cloud

AWS is responsible for protecting the infrastructure that runs AWS services.

Key responsibilities include:

- **Physical Security:** Protecting AWS data centers, buildings, and physical equipment.
- **Infrastructure Security:** Securing servers, storage devices, and networking infrastructure.
- **Hardware Maintenance:** Maintaining and replacing physical hardware.
- **Virtualization Layer:** Securing the virtualization infrastructure used to provide cloud services.
- **Global Infrastructure:** Protecting AWS Regions, Availability Zones, and networking facilities.
- **Environmental Protection:** Providing power, cooling, and physical safeguards.

**Examples of AWS-managed services and infrastructure:**
- Data centers and physical servers
- Networking infrastructure
- Storage hardware
- Virtualization infrastructure

## 3. Customer Responsibilities – Security in the Cloud

Customers are responsible for securing their AWS resources, applications, and data.

Key responsibilities include:

- **Identity and Access Management:** Managing IAM users, roles, policies, and permissions.
- **Data Protection:** Encrypting sensitive data and managing encryption keys.
- **Network Security:** Configuring VPCs, security groups, network ACLs, and firewalls.
- **Operating System Security:** Applying patches and maintaining operating systems on Amazon EC2.
- **Application Security:** Protecting applications against vulnerabilities and attacks.
- **Access Control:** Enforcing least-privilege access and multi-factor authentication (MFA).
- **Logging and Monitoring:** Monitoring activities using CloudWatch and CloudTrail.
- **Backup and Recovery:** Creating backups and implementing disaster recovery plans.

## 4. Shared Responsibility by AWS Service Type

Customer responsibilities vary depending on the AWS service model.

| Service Type | AWS Responsibility | Customer Responsibility |
|---|---|---|
| IaaS (EC2) | Physical infrastructure, networking, and virtualization | OS, applications, data, firewall configuration, and IAM |
| PaaS (RDS) | Infrastructure, operating system, database platform, and managed maintenance | Data, database access, permissions, and configuration |
| SaaS (e.g., Amazon S3) | Underlying infrastructure and service operation | Data classification, access policies, encryption settings, and data protection |

*Note: Exact responsibilities depend on the service and its configuration.*

## 5. Practical AWS Examples

### Example 1: Amazon EC2

AWS manages:
- Physical servers and data centers.
- Hardware and virtualization.
- Underlying networking infrastructure.

Customer manages:
- Operating system updates and patches.
- Application installation and configuration.
- IAM permissions.
- Security group rules.
- Data encryption and backups.

### Example 2: Amazon S3

AWS manages:
- Storage infrastructure.
- Physical hardware.
- Service availability and underlying infrastructure.

Customer manages:
- Bucket policies and access permissions.
- Data classification.
- Encryption configuration and key access.
- Data retention and backup requirements.

### Example 3: Amazon RDS

AWS manages:
- Physical infrastructure.
- Database software platform maintenance.
- Managed database infrastructure and supported automated maintenance.

Customer manages:
- Database users and permissions.
- Data protection.
- Network access configuration.
- Database settings that AWS exposes to customers.

## 6. Important AWS Security Services

| AWS Service | Purpose |
|---|---|
| IAM | Identity and access management |
| IAM Identity Center | Centralized workforce access |
| AWS KMS | Encryption key management |
| CloudTrail | API activity logging |
| CloudWatch | Monitoring and alerting |
| AWS Config | Resource configuration tracking |
| GuardDuty | Threat detection |
| Security Hub | Centralized security findings |
| Inspector | Vulnerability management |
| AWS Backup | Centralized backup management |

## 7. Key Takeaways

- AWS is responsible for **Security of the Cloud**.
- Customers are responsible for **Security in the Cloud**.
- Customer responsibilities vary depending on the AWS service.
- Using managed services reduces some operational responsibilities, but does not eliminate customer security responsibilities.
- Both AWS and customers must fulfill their responsibilities to maintain a secure cloud environment.
