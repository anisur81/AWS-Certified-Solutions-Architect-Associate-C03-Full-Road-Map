# 1.1.2: AWS federated access and identity services (for example, IAM, AWS IAM Identity Center)

## What is IAM Identity Center?
<a name="what-is"></a>

AWS IAM Identity Center is the AWS solution for connecting your workforce users to AWS managed applications such as Kiro and Amazon Quick, and other AWS resources. You can connect your existing identity provider and synchronize users and groups from your directory, or create and manage your users directly in IAM Identity Center. You can then use IAM Identity Center for either or both of the following:
+ User access to applications
+ User access to AWS accounts

## Why use IAM Identity Center?
<a name="features"></a>

IAM Identity Center streamlines and simplifies workforce user access to applications or AWS accounts, or both, through the following key capabilities.

**Integration with AWS managed applications**  
[AWS managed applications](awsapps.md) such as Kiro and Amazon Redshift integrate with IAM Identity Center. IAM Identity Center provides AWS managed applications with a common view of users and groups.

**Trusted identity propagation across applications **  
With trusted identity propagation, AWS managed applications such as Amazon Quick can securely share a user’s identity with other AWS managed applications such as Amazon Redshift and authorize access to AWS resources based on the user’s identity. You can more easily audit user activity because CloudTrail events are logged based on the user and the actions the user initiated. This makes it easier to understand who accessed what. 

**One point of federation to simplify user access to AWS**  
By providing one point of federation, IAM Identity Center reduces the administrative effort required to use multiple AWS managed applications and AWS accounts. 

**Ability to manage workforce access to multiple AWS accounts**  
IAM Identity Center gives you options to manage centrally your workforce access to AWS accounts:  

**Two instance types**  
IAM Identity Center supports two types of instances: *organization instances* and *account instances*. An organization instance is the best practice. It's the only instance that enables you to manage access to AWS accounts and it is recommended for all production use of applications. An organization instance is deployed in the AWS Organizations management account and gives you a single point from which to manage user access across AWS.   
Account instances are bound to the AWS account in which they are enabled. Use account instances of IAM Identity Center only to support isolated deployments of select AWS managed applications. For more information, see [Organization and account instances of IAM Identity Center](identity-center-instances.md).

**User-friendly web portal access for your users**  
The AWS access portal is a user-friendly web portal that provides your users with seamless access to all their assigned applications, AWS accounts, or both.

**Multi-Region access to AWS accounts and applications**  
When you replicate your IAM Identity Center instance to additional Regions, your workforce can access their assigned AWS accounts and applications through all enabled Regions, and they can deploy AWS managed applications in each enabled Region.


### In AWS, IAM determines:
- Who can access AWS resources?
- What actions can they perform?
- Which resources can they access?
- Under what conditions is access allowed?

## What is Identity Federation?
Identity federation allows users to access AWS resources using identities managed by an external identity provider (IdP), rather than maintaining separate IAM user credentials for every AWS account.

An Identity Provider is a system responsible for managing and verifying user identities.

Examples include:
- Microsoft Entra ID.
- Active Directory Federation Services (AD FS).
- Okta.
- Google Workspace.
- Other compatible enterprise identity providers.
  
### Why Do Organizations Need Federation?
Imagine an international company with:
- 500 employees.
- 20 AWS accounts.
- Multiple development teams.
- Security and compliance teams.
- Centralized employee identity management.
Without federation, administrators may need to manage separate IAM users and credentials across many accounts.

### This creates problems:
- Difficult user lifecycle management.
- Multiple credentials.
- Complex access administration.
- Delayed employee offboarding.
- Increased credential-management risks.
With federation, employees can authenticate using the organization's central identity system and receive access to authorized AWS accounts.

Conceptually:
1. An employee opens the AWS access portal.
2. The employee authenticates with the organization's identity provider.
3. The identity provider verifies the employee's identity.
4. The identity provider provides a trusted authentication assertion or token.
5. AWS validates the federation trust.
6. AWS provides access through an authorized role or IAM Identity Center permission set.
7. The employee accesses only the permitted AWS resources.

## Benefits of Identity Federation

| Benefit | Explanation |
|---|---|
| Centralized Identity | Employees use an organizational identity to access authorized AWS accounts and applications. |
| Reduced Credential Management | Reduces the need to manage separate AWS user credentials for each account. |
| Centralized Offboarding | Employee access can be disabled centrally through the identity management process. |
| MFA Integration | Supports integration with enterprise authentication systems to enforce Multi-Factor Authentication (MFA). |
| Scalability | Supports large organizations and centralized access management across multiple AWS accounts. |
| Better Governance | Access can be assigned and managed according to employee roles and job responsibilities. |
