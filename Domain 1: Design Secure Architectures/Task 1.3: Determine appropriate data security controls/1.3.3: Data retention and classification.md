# Data retention and classification


**Data classification** is the process of categorizing data according to its sensitivity, confidentiality, business value, and regulatory requirements.

**Data retention** defines how long data must be stored, when it should be archived, and when it should be securely deleted.

AWS provides services and features to help organizations classify, protect, retain, archive, and dispose of data securely.

**Key objectives:**
- Identify and classify sensitive data.
- Apply appropriate security controls.
- Define data retention policies.
- Automate data lifecycle management.
- Reduce storage costs.
- Meet legal and compliance requirements.

## 2. Data Classification Levels

Organizations can establish classification levels based on business requirements.

| Classification | Description | Examples |
|---|---|---|
| Public | Information available to everyone | Public websites, marketing materials |
| Internal | Information intended for employees | Internal documentation |
| Confidential | Sensitive business information | Customer information, financial reports |
| Restricted | Highly sensitive information | Passwords, payment data, personal records |

**AWS best practices:**
- Apply classification as early as possible during data ingestion.
- Use tags and metadata to identify sensitive resources.
- Encrypt sensitive information.
- Apply least-privilege access controls.
- Monitor data access.
- Review classification regularly.

Reference: https://docs.aws.amazon.com/wellarchitected/latest/framework/sec_data_classification.html

## 3. Data Retention and Lifecycle Management

Data retention policies determine how long information must remain available.

A typical data lifecycle includes:

1. Data creation or ingestion.
2. Data classification.
3. Data storage and processing.
4. Data access and usage.
5. Data archival.
6. Data expiration and secure deletion.

Retention policies should consider:
- Legal and regulatory requirements.
- Business requirements.
- Data sensitivity.
- Backup requirements.
- Storage costs.
- Data deletion requirements.

### AWS Services for Data Lifecycle Management

| AWS Service | Purpose |
|---|---|
| Amazon S3 Lifecycle | Automatically transition or expire objects |
| AWS Backup | Centralized backup management |
| Amazon S3 Glacier | Long-term archival storage |
| Amazon Data Lifecycle Manager | Automate EBS snapshot and AMI lifecycle |
| Amazon Macie | Discover sensitive data in S3 |
| AWS Config | Assess resource configurations |
| AWS CloudTrail | Record account activity and API events |

## 4. Amazon S3 Lifecycle Management

Amazon S3 Lifecycle policies automatically transition objects between storage classes or expire objects after a specified period.

**Example retention policy:**

| Data age | Storage class / action |
|---|---|
| 0–30 days | S3 Standard |
| 31–90 days | S3 Standard-IA |
| 91–365 days | S3 Glacier Flexible Retrieval |
| After 365 days | Expire or delete, if permitted |

*This is an example policy, not a universal AWS recommendation.*

**Important features:**
- Transition objects to lower-cost storage classes.
- Archive infrequently accessed information.
- Automatically expire objects.
- Configure separate rules using object prefixes or tags.
- Manage current and noncurrent object versions.

Documentation: https://docs.aws.amazon.com/AmazonS3/latest/userguide/object-lifecycle-mgmt.html

## 5. Amazon S3 Object Lock

S3 Object Lock protects objects using a Write Once Read Many (WORM) model.

It prevents objects from being deleted or overwritten during a defined retention period.

### Retention Modes

| Mode | Description |
|---|---|
| Governance Mode | Authorized users with special permissions can bypass retention protection |
| Compliance Mode | Protected object versions cannot be deleted or have their retention shortened during the retention period |

**Legal Hold:**
- Prevents object deletion indefinitely until the legal hold is removed.
- Independent of the configured retention period.

**Important requirements:**
- S3 Versioning must be enabled.
- Object Lock must be enabled.
- Choose retention settings according to compliance requirements.

Documentation: https://docs.aws.amazon.com/AmazonS3/latest/userguide/object-lock.html

## 6. Amazon Macie – Sensitive Data Discovery

Amazon Macie is a data security service that discovers and helps protect sensitive data stored in Amazon S3.

**Key capabilities:**
- Discover personally identifiable information (PII).
- Identify sensitive data in S3 buckets.
- Detect potentially exposed sensitive information.
- Use managed and custom data identifiers.
- Generate findings for security investigations.

**Example use case:**

An organization stores customer records in multiple S3 buckets. Amazon Macie helps identify buckets containing sensitive customer information so the organization can apply appropriate access and encryption controls.

Documentation: https://docs.aws.amazon.com/macie/latest/user/what-is-macie.html

## 7. AWS Backup and Data Protection

AWS Backup provides centralized backup management across supported AWS services.

**Key capabilities:**
- Create backup plans.
- Schedule automated backups.
- Define backup retention periods.
- Manage backup vaults.
- Copy backups across AWS Regions and accounts.
- Apply backup access controls.

**AWS Backup Vault Lock:**
- Provides additional protection against backup deletion.
- Supports governance and compliance retention controls.
- Helps protect backups from accidental or malicious deletion.

Documentation: https://docs.aws.amazon.com/aws-backup/latest/devguide/whatisbackup.html

## 8. AWS Security and Governance Best Practices

| Requirement | Recommended AWS feature |
|---|---|
| Discover sensitive S3 data | Amazon Macie |
| Encrypt data at rest | AWS KMS |
| Encrypt data in transit | TLS |
| Control data access | AWS IAM |
| Monitor API activity | AWS CloudTrail |
| Assess configuration compliance | AWS Config |
| Protect S3 objects from deletion | S3 Object Lock |
| Automate S3 archival | S3 Lifecycle |
| Centralize backups | AWS Backup |
| Enforce backup retention | AWS Backup Vault Lock |

### Important Design Principles

1. Apply least-privilege access.
2. Encrypt sensitive data at rest and in transit.
3. Separate production and backup access.
4. Use centralized logging and monitoring.
5. Automate retention and archival.
6. Follow legal retention requirements.
7. Delete data securely when retention expires.
8. Test backup restoration regularly.
