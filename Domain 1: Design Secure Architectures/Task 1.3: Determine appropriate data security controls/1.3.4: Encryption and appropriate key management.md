# Encryption and appropriate key management

**Encryption** is a security technique that converts readable data (plaintext) into unreadable data (ciphertext) using cryptographic algorithms and encryption keys. It protects sensitive information against unauthorized access, disclosure and modification.
AWS provides encryption capabilities through services such as AWS Key Management Service (AWS KMS), AWS CloudHSM and the AWS Encryption SDK.

**Objectives:**
- Protect sensitive data at rest and in transit.
- Maintain data confidentiality and integrity.
- Control access to encryption keys.
- Implement secure key storage and rotation.
- Meet organizational and regulatory requirements.

## 2. Types of Encryption

### 2.1 Encryption at Rest

Encryption at rest protects stored data from unauthorized access.

Examples:
- Amazon S3: Server-side encryption (SSE-S3, SSE-KMS).
- Amazon EBS: Encrypt volumes and snapshots.
- Amazon RDS: Encrypt databases and backups.
- Amazon EFS: Encrypt file systems.
- Amazon DynamoDB: Encryption at rest.

**Best practices:**
- Enable encryption by default wherever supported.
- Use AWS KMS for centralized key management.
- Apply customer-managed keys when granular control is required.
- Restrict decryption permissions to authorized users and services.

### 2.2 Encryption in Transit

Encryption in transit protects information while it moves between applications, services and networks.

Examples:
- HTTPS using TLS.
- TLS for application-to-database connections.
- Secure communication between microservices.
- AWS API communication using TLS.

**Best practices:**
- Use HTTPS instead of HTTP.
- Enforce modern TLS configurations.
- Validate certificates.
- Avoid transmitting sensitive information through unencrypted connections.

### 2.3 Client-Side and Server-Side Encryption

| Feature | Server-Side Encryption | Client-Side Encryption |
|---|---|---|
| Encryption location | AWS service or receiving system | Client application |
| Key management | AWS KMS or service-managed keys | Customer-controlled |
| Complexity | Generally lower | Generally higher |
| Use case | S3, EBS, RDS | Sensitive application data |

Client-side encryption can be implemented using the AWS Encryption SDK.

## 3. AWS Key Management Service (AWS KMS)

AWS KMS is a managed service that allows organizations to create, manage and control cryptographic keys used to protect data.

**Key features:**
- Centralized encryption key management.
- Integration with AWS services.
- Access control through IAM and key policies.
- Automatic and on-demand key rotation options.
- Audit logging through AWS CloudTrail.
- Integration with AWS CloudHSM and custom key stores.

AWS KMS protects its key material using hardware security modules (HSMs).

### 3.1 Types of AWS KMS Keys

| Key Type | Description |
|---|---|
| AWS Owned Keys | Managed entirely by AWS; customers have no direct visibility or control. |
| AWS Managed Keys | Created and managed by AWS for use in specific AWS services. |
| Customer Managed Keys | Created and controlled by customers with configurable permissions and policies. |

**When to use Customer Managed Keys:**
- Strict access control requirements.
- Regulatory and compliance requirements.
- Cross-account encryption access.
- Custom key rotation and lifecycle management.
- Centralized security governance.

## 4. Appropriate Key Management

Effective key management is essential for protecting encrypted information.

### 4.1 Key Creation

- Use AWS KMS to generate cryptographic keys.
- Select appropriate symmetric or asymmetric key types.
- Follow approved cryptographic algorithms and key strengths.
- Separate keys according to data classification and workload requirements.

### 4.2 Key Storage

- Store encryption keys securely using AWS KMS.
- Use AWS CloudHSM when dedicated HSM control is required.
- Never store plaintext encryption keys in source code or GitHub.
- Avoid exposing keys through application logs or configuration files.

### 4.3 Key Access Control

Apply the principle of least privilege.

- Use IAM policies and KMS key policies.
- Grant encryption and decryption permissions only to authorized roles.
- Separate key administrators from key users.
- Use IAM roles instead of long-term credentials.
- Restrict cross-account key usage.
- Protect key deletion and modification permissions.

### 4.4 Key Rotation

Key rotation replaces existing cryptographic key material or changes to a new key.

AWS KMS supports automatic and on-demand rotation for supported customer-managed keys.

**Best practices:**
- Follow regulatory and organizational rotation requirements.
- Enable automatic rotation where supported and required.
- Use manual rotation when automatic rotation is unavailable.
- Maintain access to historical key material needed for decryption.
- Test applications after changing encryption keys.

**Important:** Rotating a KMS key does not automatically re-encrypt existing data with a completely different KMS key. For example, S3 objects may need to be rewritten to use a new customer-managed key.

### 4.5 Key Deletion and Recovery

- Restrict permissions to schedule key deletion.
- Review key dependencies before deletion.
- Use the KMS deletion waiting period (7–30 days).
- Monitor deletion requests using CloudTrail.
- Cancel scheduled deletion if it was requested accidentally.

Deleting a KMS key can make encrypted data permanently unrecoverable.

## 5. Envelope Encryption

Envelope encryption is a technique in which one encryption key protects another encryption key.

**How it works:**

1. AWS KMS generates a data encryption key (DEK).
2. The application uses the plaintext DEK to encrypt the actual data.
3. AWS KMS protects the DEK using a KMS key.
4. The encrypted data and encrypted DEK are stored together.
5. During decryption, the application requests AWS KMS to decrypt the DEK.
6. The application uses the recovered DEK to decrypt the data.

**Benefits:**
- Reduces direct KMS encryption operations on large datasets.
- Improves application scalability.
- Separates data encryption from key encryption.
- Supports secure client-side encryption.

The AWS Encryption SDK supports envelope encryption.

|---|---|

| AWS CloudHSM | Dedicated HSM-based key management |

| Amazon RDS | Database encryption |
| AWS CloudTrail | Audit KMS API activities |

## 7. Monitoring and Security Best Practices

- Enable AWS CloudTrail to monitor KMS API activities.
- Use AWS Config to evaluate encryption configurations.
- Use AWS Security Hub for security posture monitoring.
- Implement AWS Organizations SCPs to enforce security guardrails.
- Apply encryption by default.
- Separate production and development encryption keys where appropriate.
- Monitor unauthorized key usage.
- Restrict key disabling and deletion operations.
- Review key policies regularly.
- Maintain documented key ownership and recovery procedures.
