# 1.3.1: Data access and governance

## 1. Introduction
Data access and governance in AWS refer to the processes, policies, and security controls used to manage, protect, monitor, and govern data across AWS resources and services.
AWS provides tools and services that help organizations ensure that only authorized users, applications, and services can access sensitive data. Data governance also helps maintain data confidentiality, integrity, availability, compliance, and accountability.

Main objectives:

- Protect sensitive and confidential information.
- Control who can access data and AWS resources.
- Enforce least-privilege access.
- Maintain data security and regulatory compliance.
- Monitor and audit data access activities.
- Establish consistent data management policies.

## 2. Key Concepts of Data Access and Governance

### 2.1 Identity and Access Management (IAM)

AWS Identity and Access Management (IAM) controls who can access AWS resources and what actions they can perform.

Key features:

- IAM Users: Individual identities for accessing AWS resources.
- IAM Groups: Collections of IAM users with common permissions.
- IAM Roles: Temporary credentials for users, applications, and AWS services.
- IAM Policies: JSON documents that define permissions.
- Multi-Factor Authentication (MFA): Adds an additional authentication layer.

Example: A developer can access development S3 buckets but cannot access production databases.

### 2.2 Data Access Control

Data access control ensures that only authorized identities can access specific datasets.

AWS provides several mechanisms:

| Mechanism               | Purpose                                                       |
| ----------------------- | ------------------------------------------------------------- |
| IAM Policies            | Control access to AWS services and resources.                 |
| Resource-Based Policies | Define permissions directly on resources, such as S3 buckets. |
| S3 Bucket Policies      | Control access to objects and buckets.                        |
| AWS KMS Key Policies    | Control access to encryption keys.                            |
| AWS Lake Formation      | Manage fine-grained permissions for data lakes.               |
| VPC Endpoint Policies   | Control access through VPC endpoints.                         |

### 2.3 Data Encryption

Encryption protects data from unauthorized access.

- Encryption at Rest: Protects stored data.
- Encryption in Transit: Protects data moving between systems.
- AWS Key Management Service (KMS): Creates and manages encryption keys.
- AWS CloudHSM: Provides dedicated hardware security modules for cryptographic operations.

### 2.4 Data Governance

Data governance establishes policies and responsibilities for managing organizational data.

Important governance activities include:

- Data classification: Identify public, internal, confidential, and sensitive data.
- Data ownership: Assign responsibility for datasets.
- Data access management: Define who can access specific information.
- Data retention: Establish how long data should be stored.
- Data lifecycle management: Manage data from creation to deletion.
- Compliance management: Follow applicable regulatory and organizational requirements.

## 3. Important AWS Services for Data Governance

| AWS Service           | Purpose                                                  |
| --------------------- | -------------------------------------------------------- |
| AWS IAM               | Manages user identities and permissions.                 |
| AWS Lake Formation    | Centrally manages data lake access and governance.       |
| AWS Glue Data Catalog | Maintains metadata about datasets.                       |
| Amazon S3             | Stores structured and unstructured data.                 |
| AWS KMS               | Manages encryption keys.                                 |
| AWS CloudTrail        | Records AWS API activity for auditing.                   |
| Amazon Macie          | Discovers and helps protect sensitive data stored in S3. |
| AWS Config            | Evaluates and monitors AWS resource configurations.      |

## 4. Fine-Grained Data Access Control

AWS Lake Formation supports fine-grained access control, allowing administrators to grant permissions at different levels.

- Database-level: Access to specific databases.
- Table-level: Access to selected tables.
- Column-level: Access to specific columns.
- Row-level: Access to selected records.
- Cell-level: Access to specific data cells.

Example:

A company stores employee information in an Amazon S3 data lake.

| Department | Access permissions                                 |
| ---------- | -------------------------------------------------- |
| HR         | Employee names, salaries, and personal information |
| Finance    | Salary and financial information                   |
| IT         | Technical information                              |
| Management | Approved organizational reports                    |

AWS Lake Formation helps enforce these permissions according to organizational policies.&#x20;

## 5. Best Practices for Data Access and Governance

1. Follow the principle of least privilege.
2. Enable MFA for privileged users.
3. Use IAM roles instead of long-term credentials wherever possible.
4. Encrypt sensitive data at rest and in transit.
5. Use AWS Lake Formation for centralized data lake governance.
6. Apply resource-based policies to protect data resources.
7. Enable AWS CloudTrail for auditing API activities.
8. Classify sensitive data and apply appropriate access policies.
9. Regularly review IAM permissions and access policies.
10. Establish data retention and deletion policies.

## 6. Practical Example

Scenario: Centralized Data Governance in AWS

An organization has three departments: Development, Finance, and HR.

```
                 AWS Organization
                        |
                  AWS IAM Identity
                        |
                 IAM Roles / Policies
                        |
                 AWS Lake Formation
                        |
                 AWS Glue Data Catalog
                        |
                  Amazon S3 Data Lake
                        |
          +-------------+-------------+
          |             |             |
       Finance          HR       Development
          |             |             |
       Financial     Employee      Application
         Data          Data           Data
```

Implementation:

1. Create an Amazon S3 bucket for centralized data storage.
2. Organize datasets into department-specific folders.
3. Register the S3 data location with AWS Lake Formation.
4. Create databases and tables in AWS Glue Data Catalog.
5. Create IAM roles for Finance, HR, and Development.
6. Grant appropriate Lake Formation permissions.
7. Configure column-level and row-level access where required.
8. Enable CloudTrail to monitor AWS API activities.
9. Regularly review access permissions.

## 7. Key Takeaways

- IAM controls who can access AWS resources.
- Lake Formation provides centralized data governance.
- AWS Glue Data Catalog organizes data metadata.
- Amazon S3 provides scalable data storage.
- AWS KMS protects data through encryption.
- CloudTrail supports auditing and accountability.
- Fine-grained access control protects sensitive datasets.
