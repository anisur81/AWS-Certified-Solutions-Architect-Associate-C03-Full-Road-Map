# AWS – Secure Application Access

## 1. Introduction

**Secure Application Access** means controlling how users, applications, and services authenticate and access AWS resources.

AWS provides identity, authentication, authorization, and network security services to protect applications against unauthorized access.

Main objectives:

- Verify user and application identities.
- Control access to APIs and application resources.
- Protect sensitive data and credentials.
- Prevent unauthorized requests.
- Apply least-privilege permissions.

## 2. Important AWS Services

| AWS Service | Purpose |
|---|---|
| AWS IAM | Controls access to AWS resources using users, roles, and policies |
| Amazon Cognito | Provides user authentication and identity management |
| Amazon API Gateway | Manages and protects application APIs |
| AWS Lambda Authorizer | Validates requests and controls API access |
| AWS STS | Provides temporary security credentials |
| AWS WAF | Protects web applications against common web attacks |
| Amazon VPC | Provides network isolation and private connectivity |
| AWS KMS | Manages encryption keys |

## 3. Authentication vs Authorization

**Authentication:** Verifies who a user or application is.

Example: A user signs in using a username and password.

**Authorization:** Determines what an authenticated user or application is allowed to access.

Example: A developer can view application data but cannot delete production resources.

## 4. How Secure Application Access Works

```text
        Application User
               |
               v
        Amazon Cognito
        (Authentication)
               |
               v
          Access Token
               |
               v
        Amazon API Gateway
        (Authorization)
               |
               v
         AWS Lambda
               |
               v
       AWS Backend Resources
```

### Workflow

1. The user signs in through Amazon Cognito.
2. Cognito authenticates the user and issues tokens.
3. The application sends an access token with its API request.
4. API Gateway validates the token using an appropriate authorizer.
5. The request is authorized according to configured permissions.
6. API Gateway forwards authorized requests to backend services.

## 5. API Access Control Methods

API Gateway supports several authorization mechanisms:

- **IAM Authorization:** Uses AWS IAM permissions to control API access.
- **Amazon Cognito Authorizer:** Uses Cognito user-pool tokens to authenticate API users.
- **Lambda Authorizer:** Uses a Lambda function to evaluate incoming requests.
- **Resource Policies:** Restrict API access based on principals, source IP addresses, or VPC endpoints.

## 6. Security Best Practices

1. Apply least-privilege IAM permissions.
2. Use temporary credentials instead of long-term AWS access keys.
3. Enable MFA for privileged users.
4. Validate authentication tokens.
5. Protect API endpoints using appropriate authorization.
6. Use HTTPS to encrypt data in transit.
7. Store application secrets securely using AWS Secrets Manager.
8. Restrict access to private backend resources.
9. Use AWS WAF to protect public web applications.
10. Monitor access and API activity using CloudTrail and CloudWatch.

## 7. Key Takeaways

- Authentication verifies identity.
- Authorization controls permissions.
- Amazon Cognito manages application user authentication.
- API Gateway provides API access control.
- IAM controls access to AWS resources.
- Lambda Authorizers support custom authorization logic.
- Secure application access requires identity, permission, and network controls.

**Remember:** Authenticate users, authorize every request, and grant only the minimum permissions required.
