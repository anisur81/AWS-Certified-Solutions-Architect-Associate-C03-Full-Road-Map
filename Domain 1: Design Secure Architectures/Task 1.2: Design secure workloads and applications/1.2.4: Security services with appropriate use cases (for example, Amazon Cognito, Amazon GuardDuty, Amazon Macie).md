#  Security services with appropriate use cases (for example, Amazon Cognito, Amazon GuardDuty, Amazon Macie)

## AWS Security Services with Appropriate Use Cases

## 1. Introduction

AWS provides multiple security services to protect cloud infrastructure, applications, identities, workloads, and sensitive data.

These services help organizations implement:

- Identity and access management.
- Threat detection and monitoring.
- Data protection and encryption.
- Infrastructure and network security.
- Application protection.
- Security compliance and auditing.

# The three services serve different security purposes:

- Amazon Cognito: Protects application users through authentication and access management.
- Amazon GuardDuty: Detects suspicious activity and potential threats in AWS environments.
- Amazon Macie: Discovers sensitive data and identifies data security risks, particularly in Amazon S3.


## Important Security Services: Detailed Use Cases

### A. Amazon Cognito
Amazon Cognito is an AWS managed service that provides authentication, authorization, and user identity management for web and mobile applications.

It allows application developers to implement user registration, login, logout, password recovery, multi-factor authentication (MFA), and access to protected application resources without building a complete identity management system from scratch.

For example, imagine you are developing an online banking application.

Users need to:
- Register an account.
- Log in using an email address and password.
- Verify their email address or phone number.
- Reset forgotten passwords.
- Enable multi-factor authentication.
- Access their personal banking information securely.
- Connect to AWS resources when authorized.
Amazon Cognito provides the identity-management capabilities needed to implement these features.

#### Why do we need Amazon Cognito?

Without Cognito, developers may need to build and maintain:
- User registration and login systems.
- Password storage and security.
- Authentication APIs.
- Password reset functionality.
- MFA mechanisms.
- User session management.
- Token generation and validation.
- Federation with external identity providers.
Cognito provides managed capabilities for these requirements.

**Important**: Cognito manages application identities. It is not a replacement for AWS IAM, and it does not automatically provide users with permission to access every AWS resource.

**Best use case:** Secure customer identity management for web and mobile applications.



 #### AWS Cognito – Security Features

Amazon Cognito provides multiple security capabilities to protect application identities.

| Security Feature | Purpose |
|---|---|
| Multi-Factor Authentication (MFA) | Adds an additional authentication factor to verify user identity beyond the password. |
| Password Policies | Enforces password requirements, including minimum length, complexity, and other password rules. |
| Account Recovery | Allows users to recover access to their accounts through configured recovery methods, such as email or SMS. |
| Token Expiration | Limits the lifetime of access, ID, and refresh tokens to reduce the risk of unauthorized access. |
| Token Revocation | Revokes supported tokens and prevents their continued use for authorized access. |
| Adaptive Authentication | Applies additional authentication checks based on user behavior, device information, and risk signals. |
| AWS WAF Integration | Helps protect Amazon Cognito User Pools against malicious web requests and common web-based threats. |
| Lambda Triggers | Customizes authentication, registration, account confirmation, and other user authentication workflows using AWS Lambda functions. |
| Advanced Security / Threat Protection | Helps detect and respond to suspicious authentication activities, compromised credentials, and potential account takeover attempts. |

## B. Amazon GuardDuty

**Purpose:** Detect potential threats and malicious activity in AWS environments.
**Best use case:** Continuous threat detection for AWS accounts, EC2, containers, S3, and other supported workloads.

**Amazon GuardDuty** is a fully managed threat-detection service that continuously monitors supported AWS accounts, workloads, runtime activity, and data for malicious activity and unauthorized behavior. It uses threat intelligence, machine learning (ML), anomaly detection, and behavioral analysis to identify suspicious patterns.

GuardDuty is primarily a detective security control. It helps identify potential threats, but it does not replace preventive controls such as IAM policies, security groups, network firewalls, encryption, patching, or secure application design.

### Why use GuardDuty?
- Detect suspicious use of AWS credentials and unusual API activity. 
- Identify communication with known malicious IP addresses or domains.
- Detect reconnaissance, possible account compromise, and multi-stage   attacks.
- Find indicators of compromise affecting supported compute workloads.
- Monitor supported S3, database, container, serverless, backup, and   AI workloads through protection plans.
- Centralize findings across multiple AWS accounts and Regions.
- Integrate findings with investigation and response workflows.

### How GuardDuty Works
GuardDuty analyzes supported AWS security signals. It compares activity with threat intelligence and expected behavioral patterns. When it identifies potentially malicious activity, it creates a finding.

```
AWS accounts, workloads, and data
                 |
                 v
        Supported AWS signals
  CloudTrail management events, VPC Flow Logs,
       DNS logs, and enabled protection plans
                 |
                 v
           Amazon GuardDuty
   Threat intelligence + anomaly detection
       + machine-learning analysis
                 |
                 v
           Security finding
                 |
        +--------+---------+
        |        |         |
        v        v         v
     Console  EventBridge Security Hub
                 |
                 v
       SIEM / notification / automation
                 |
                 v
        Security investigation
 ```

### Understanding GuardDuty Findings
A finding is a security alert describing suspicious activity detected by GuardDuty. It provides information to help a security analyst investigate.

A finding commonly contains:
- Finding type: A structured name describing the threat category.
- Severity: Relative risk level.
- Resource: The affected AWS resource, account, or identity.
- Activity details: Observed behavior, such as API activity or   network communication.
- Time information: When the activity was first and most recently   observed.
- Additional context: IP addresses, domains, user agents, or other   indicators, when available.

## C. Amazon Macie

**Purpose:** Discover and protect sensitive data stored in Amazon S3.
**Best use case:** Discover PII and other sensitive information in S3 and identify potential data exposure risks.

**Amazon Macie** is a fully managed data security and data privacy service from AWS. It uses machine learning and pattern matching to automatically discover, classify, and protect sensitive data stored in Amazon S3. It also gives you visibility into how that data is stored and who can access it.

In short: Macie finds sensitive data (like PII, financial data, credentials) in your S3 buckets and alerts you to security risks around it.

### Why Do We Need Macie?

Organizations often store massive amounts of data in S3: logs, customer records, backups, documents. Over time, nobody knows exactly:

Which buckets contain personal or financial information
Which buckets are publicly accessible
Whether sensitive data is properly encrypted

Manually checking this at scale is impossible. Macie automates it.

#### Key Features
1. Automated Sensitive Data Discovery

Macie continuously evaluates your S3 environment and can run automated sensitive data discovery, sampling objects across all your buckets to build a picture of where sensitive data lives without you configuring individual jobs.

2. S3 Bucket Inventory and Posture Assessment

Macie gives you a dashboard and inventory of all S3 buckets in your account (or across your organization) and evaluates:

Public accessibility (via ACLs, bucket policies, Block Public Access settings)
Encryption status (SSE-S3, SSE-KMS, or unencrypted)
Sharing with other AWS accounts or outside your organization
Replication to external accounts
3. Sensitive Data Detection

Macie detects two categories of sensitive data:

Managed data identifiers (built-in by AWS):

Personally Identifiable Information (PII): names, addresses, passport numbers, driver’s license, national IDs
Financial information: credit card numbers, bank account numbers
Credentials: AWS secret access keys, private keys, API keys
Protected health information (PHI)

Custom data identifiers (defined by you):

Written using regular expressions (regex)
Can include keywords and proximity rules (e.g., an employee ID pattern near the word “Employee”)
Can include ignore words to reduce false positives

You can also use allow lists to tell Macie to ignore specific text or patterns that are not actually sensitive.

4. Sensitive Data Discovery Jobs

You can create one-time or recurring jobs that scan specific S3 buckets or objects. You choose:

Which buckets/objects to include
Scheduling (one-time, daily, weekly, monthly)
Which managed and custom identifiers to use
Sampling depth (to control cost)

5. Findings

When Macie detects an issue, it generates a finding. There are two types:

|Type|	Description|	Examples|
|--|--|--|

|Policy findings|	Problems with bucket security/configuration	|Block Public Access disabled, bucket made public, encryption disabled, bucket shared externally|
|Sensitive data findings	| Sensitive data discovered inside objects|	Credit card numbers found, credentials found, PII found|

Each finding includes a severity (Low, Medium, High), details about the affected bucket/object, and the types and counts of sensitive data found. Findings are stored for 90 days.
