# 1.2.2: AWS service endpoints & Control ports, protocols, and network traffic on AWS

## AWS Service Endpoints

## 1. What are AWS Service Endpoints?

An **AWS Service Endpoint** is a URL that acts as an entry point for connecting to an AWS service through API requests.

Applications, AWS SDKs, and AWS CLI use service endpoints to communicate with AWS services.

For example:
- Amazon EC2
- Amazon S3
- Amazon DynamoDB
- AWS Systems Manager

AWS SDKs and AWS CLI automatically use the default endpoint for the selected service and Region.

## 2. Types of AWS Service Endpoints

### A. Regional Endpoints

Regional endpoints allow applications to communicate with AWS services in a specific AWS Region.

**General format:**

```text
https://service-code.region-code.amazonaws.com
```

**Example:**

```text
https://ec2.ap-southeast-1.amazonaws.com
```

This is an Amazon EC2 endpoint in the Singapore Region.

### B. Global Endpoints

Some AWS services provide global endpoints that operate across AWS Regions.

Examples:
- AWS IAM
- AWS Organizations
- Amazon CloudFront
- Amazon Route 53
- AWS Global Accelerator

### C. Dual-Stack Endpoints

Dual-stack endpoints support both IPv4 and IPv6 traffic.

**General format:**

```text
https://service-code.region-code.api.aws
```

### D. FIPS Endpoints

FIPS endpoints support connections using cryptographic implementations that meet applicable Federal Information Processing Standards (FIPS) requirements.

They are useful for workloads with specific regulatory or compliance requirements.

## 3. AWS Service Endpoint Example

| AWS Service | Example Endpoint |
|---|---|
| Amazon EC2 | ec2.ap-southeast-1.amazonaws.com |
| Amazon DynamoDB | dynamodb.ap-southeast-1.amazonaws.com |
| Amazon SQS | sqs.ap-southeast-1.amazonaws.com |

*Examples use the Singapore Region.*

## 4. AWS CLI Example

Check AWS EC2 Regions using a specific endpoint:

```bash
aws ec2 describe-regions \
  --region us-east-2 \
  --endpoint-url https://ec2.us-east-2.amazonaws.com
```

## 5. Key Takeaways

- Service endpoints provide entry points for AWS API communication.
- Regional endpoints connect to services in specific Regions.
- Global endpoints support services operating across Regions.
- Dual-stack endpoints support IPv4 and IPv6.
- FIPS endpoints support applicable FIPS requirements.
- AWS CLI and SDKs normally select endpoints automatically.

**Remember:** AWS service endpoints allow applications and tools to communicate securely with AWS services through API requests.

# AWS: Control Ports, Protocols, and Network Traffic

## 1. Introduction

Controlling ports, protocols, and network traffic is an important part of AWS network security.

Amazon Virtual Private Cloud (VPC) provides security features to control incoming and outgoing network communication between AWS resources and external networks.

The main objectives are:

- Prevent unauthorized network access.
- Allow only required ports and protocols.
- Control inbound and outbound traffic.
- Protect EC2 instances, databases, and applications.
- Reduce the network attack surface.

## 2. Important Network Concepts

| Concept          | Description                                                    |
| ---------------- | -------------------------------------------------------------- |
| Port             | A logical communication endpoint used by network applications. |
| Protocol         | Defines how devices communicate, such as TCP, UDP, and ICMP.   |
| Inbound Traffic  | Network traffic entering an AWS resource.                      |
| Outbound Traffic | Network traffic leaving an AWS resource.                       |
| Firewall         | Controls network traffic based on defined security rules.      |
| CIDR             | Represents an IP address range, such as `10.0.0.0/16`.         |

## 3. AWS Security Groups

A **Security Group** acts as a virtual firewall that controls inbound and outbound traffic for associated AWS resources, such as EC2 instances.

Key features:

- Stateful traffic filtering.
- Supports inbound and outbound rules.
- Allows traffic based on protocol, port, IP address, or another security group.
- Supports allow rules; traffic not explicitly allowed is denied.

**Example:**

| Type  | Protocol | Port | Source                     |
| ----- | -------- | ---- | -------------------------- |
| SSH   | TCP      | 22   | Trusted IP                 |
| HTTP  | TCP      | 80   | 0.0.0.0/0                  |
| HTTPS | TCP      | 443  | 0.0.0.0/0                  |
| MySQL | TCP      | 3306 | Application Security Group |

## 4. Network ACLs (NACLs)

A **Network Access Control List (NACL)** controls inbound and outbound traffic at the subnet level.

Key features:

- Stateless traffic filtering.
- Supports Allow and Deny rules.
- Evaluates rules in ascending numerical order.
- Return traffic must be explicitly permitted.

## 5. Security Groups vs Network ACLs

| Feature         | Security Group               | Network ACL                        |
| --------------- | ---------------------------- | ---------------------------------- |
| Level           | Resource / network interface | Subnet                             |
| Filtering       | Stateful                     | Stateless                          |
| Rules           | Allow only                   | Allow and Deny                     |
| Rule evaluation | All applicable rules         | Lowest numbered matching rule      |
| Return traffic  | Automatically allowed        | Must be explicitly allowed         |
| Primary purpose | Fine-grained resource access | Additional subnet-level protection |

## 6. Common Network Ports and Protocols

| Port | Protocol | Service              |
| ---- | -------- | -------------------- |
| 22   | TCP      | SSH                  |
| 80   | TCP      | HTTP                 |
| 443  | TCP      | HTTPS                |
| 3389 | TCP      | Windows RDP          |
| 3306 | TCP      | MySQL                |
| 5432 | TCP      | PostgreSQL           |
| 1433 | TCP      | Microsoft SQL Server |
| 53   | UDP/TCP  | DNS                  |

## 7. Other AWS Network Security Services

- **AWS Network Firewall:** Provides centralized network traffic filtering and inspection.
- **AWS WAF:** Protects web applications against common HTTP/HTTPS attacks.
- **VPC Flow Logs:** Captures information about IP traffic to and from network interfaces.
- **AWS PrivateLink:** Provides private connectivity to supported AWS services and applications.
- **Route Tables:** Control where network traffic is directed.

## 8. Best Practices

1. Allow only required ports and protocols.
2. Restrict SSH (22) and RDP (3389) to trusted sources.
3. Never expose database ports publicly.
4. Use security groups as the primary resource-level control.
5. Use NACLs as an additional subnet-level security layer.
6. Place databases and internal application servers in private subnets.
7. Review inbound and outbound rules regularly.
8. Enable VPC Flow Logs to monitor network traffic.
9. Apply least-privilege network access.
10. Use AWS Network Firewall when centralized traffic inspection is required.

## 9. Key Takeaways

- Security groups control traffic at the resource level.
- Network ACLs control traffic at the subnet level.
- TCP, UDP, and ICMP are important network protocols.
- Ports identify application communication endpoints.
- Inbound and outbound traffic must be properly controlled.
- Multiple security layers help protect AWS network resources.

**Remember:** Allow only the network traffic your application requires, and deny unnecessary access.
