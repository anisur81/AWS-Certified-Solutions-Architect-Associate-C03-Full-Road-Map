# 1.2.5: Threat vectors external to AWS (for example, DDoS, SQL injection)

## Threat Vectors External to AWS

### 1. Introduction

Threat vectors external to AWS are potential attack methods that originate outside the AWS cloud environment and target applications, networks, APIs, servers, or data hosted on AWS.

These threats can compromise application availability, confidentiality, and integrity.

Common external threats include:

- Distributed Denial of Service (DDoS)
- SQL Injection (SQLi)
- Cross-Site Scripting (XSS)
- Brute-Force Attacks
- Phishing and Credential Theft
- Malware and Ransomware
- API Attacks
- Man-in-the-Middle (MITM) Attacks

## 2. Common External Threat Vectors

### 2.1 Distributed Denial of Service (DDoS)

Definition: A DDoS attack occurs when an attacker uses multiple compromised devices to send massive amounts of traffic to a target application or server.

Impact:

- Makes applications unavailable.
- Consumes network bandwidth and computing resources.
- Disrupts business operations.
- Increases infrastructure costs.

AWS Protection:

- AWS Shield Standard
- AWS Shield Advanced
- AWS WAF
- Amazon CloudFront
- Amazon Route 53

### 2.2 SQL Injection (SQLi)

Definition: SQL injection occurs when attackers insert malicious SQL statements into application input fields to manipulate backend database queries.

Impact:

- Unauthorized database access.
- Sensitive data exposure.
- Modification or deletion of database records.
- Authentication bypass.

AWS Protection:

- AWS WAF with managed SQL injection rules.
- Input validation and parameterized queries.
- Least-privilege database permissions.
- Secure application development practices.

### 2.3 Cross-Site Scripting (XSS)

Definition: XSS occurs when attackers inject malicious scripts into web pages viewed by other users.

Impact:

- Session or cookie theft.
- Unauthorized actions on behalf of users.
- Phishing through compromised web pages.
- Exposure of sensitive information.

AWS Protection:

- AWS WAF managed rule groups.
- Input validation.
- Output encoding.
- Content Security Policy (CSP).

### 2.4 Brute-Force Attack

Definition: An attacker repeatedly attempts different passwords or credentials to gain unauthorized access to AWS-hosted applications, login portals, or administrative accounts.

Impact:

- Unauthorized account access.
- Account takeover.
- Exposure of confidential information.
- Compromised user credentials.

AWS Protection:

- AWS IAM and IAM Identity Center.
- Multi-Factor Authentication (MFA).
- AWS WAF rate-based rules.
- Amazon Cognito security features.
- Account lockout and login-attempt restrictions.

### 2.5 Phishing and Credential Theft

Definition: Phishing is a social engineering attack in which attackers trick users into revealing passwords, access keys, or other sensitive information through fake emails, websites, or messages.

Impact:

- Stolen AWS credentials.
- Unauthorized AWS resource access.
- Data breaches.
- Misuse of cloud resources.

AWS Protection:

- Enforce MFA.
- Follow IAM least-privilege principles.
- Use IAM roles instead of long-term access keys.
- Monitor suspicious activity using AWS CloudTrail.
- Use AWS GuardDuty for threat detection.

### 2.6 Malware and Ransomware

Definition: Malware is malicious software designed to compromise systems, steal information, disrupt operations, or encrypt data. Ransomware is a type of malware that encrypts data and demands payment for recovery.

Impact:

- Data encryption and loss.
- Unauthorized system access.
- Application disruption.
- Business downtime.

AWS Protection:

- Amazon GuardDuty Malware Protection.
- Amazon Inspector.
- AWS Backup.
- Amazon EBS snapshots.
- Network segmentation using Amazon VPC.

### 2.7 API Attacks

Definition: API attacks occur when attackers exploit insecure API endpoints, authentication weaknesses, excessive permissions, or application vulnerabilities.

Impact:

- Unauthorized access to application data.
- Data manipulation.
- Account takeover.
- Abuse of application functionality.

AWS Protection:

- Amazon API Gateway.
- AWS WAF.
- Amazon Cognito.
- IAM authorization.
- API throttling and request validation.

### 2.8 Man-in-the-Middle (MITM) Attack

Definition: A MITM attack occurs when an attacker intercepts communication between two parties to steal or manipulate information.

Impact:

- Credential theft.
- Sensitive data exposure.
- Communication manipulation.
- Unauthorized access.

AWS Protection:

- Use HTTPS/TLS encryption.
- Use AWS Certificate Manager (ACM).
- Enforce secure communication protocols.
- Encrypt sensitive data in transit.

## 3. AWS Security Services Mapping

| Threat vector        | Recommended AWS services         |
| -------------------- | -------------------------------- |
| DDoS                 | AWS Shield, AWS WAF, CloudFront  |
| SQL Injection        | AWS WAF                          |
| XSS                  | AWS WAF                          |
| Brute-force          | AWS WAF, IAM, Cognito            |
| Phishing             | IAM, MFA, GuardDuty              |
| Malware / Ransomware | GuardDuty, Inspector, AWS Backup |
| API Attacks          | API Gateway, AWS WAF, Cognito    |
| MITM                 | ACM, TLS/HTTPS, AWS KMS          |

## 4. AWS Security Best Practices

1. Apply the principle of least privilege.
2. Enable MFA for privileged accounts.
3. Protect internet-facing applications with AWS WAF.
4. Use AWS Shield for DDoS protection.
5. Encrypt sensitive data at rest and in transit.
6. Monitor suspicious activities using Amazon GuardDuty.
7. Enable AWS CloudTrail for API activity logging.
8. Regularly patch operating systems and applications.
9. Use secure coding practices and validate user inputs.
10. Maintain regular backups and test recovery procedures.

## 5. Key Takeaway

External threat vectors originate outside the AWS environment and target applications, infrastructure, identities, and data.

AWS provides security services such as AWS Shield, AWS WAF, Amazon GuardDuty, IAM, and Amazon Inspector to help detect, prevent, and mitigate these threats.

Important: AWS security follows the Shared Responsibility Model. AWS is responsible for security of the cloud, while customers are responsible for security in the cloud.
